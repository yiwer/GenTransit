## 1. 调研

### 1.1 现状

- 站架类型是七类字典之一，每项只有一个名称（5.7）。站架、站架模板用 `typeId` 引用字典项。
- 立面只看名称画结构：名称含"候车亭"画顶棚，含"单立柱"画一根立柱，其余画两根（`apps/web/src/components/gt/elevation.tsx` 的 `SignShelf`，M3 默认决定 16）。改个名字，画法就变了。
- 一个站架上各面的站牌在立面里左右排开，共用一组立柱；牌面下沿固定画在离地 420 mm（`POST_MM`，示意值）。
- 面有八个取值：正面、背面、A–F，编辑时可以任选，和站架的实际结构无关。

### 1.2 常见站架形式

国内做法与 OpenStreetMap 的公交立杆分类（`pole=traffic_sign / flag / totem`）对照后，归成六种结构形式：

| 形式 | 说明 | 面 | 关键尺寸 |
|---|---|---|---|
| 单立柱 | 一根柱，牌抱箍在柱前居中，或旗式伸出在柱一侧（OSM `flag`） | 单面 / 双面 | 柱高、柱径、挂法 |
| 双立柱 | 两根柱夹一块或一排牌；最常见的线路站牌 | 单面 / 双面（背靠背） | 柱高、柱径、柱到牌组边缘的距离 |
| 候车亭 | 顶棚 + 立柱，站牌装在背板、端板或立柱间的灯箱上 | 亭内 / 亭外 | 长度、顶棚进深、顶棚下沿高、立柱数、挂在背板还是端板 |
| 多面柱（图腾柱） | 三到六面的竖向导向柱，每面一组牌（OSM `totem`） | A–F | 面数、柱高、底座 |
| 附着式 | 挂在墙面，或挂在路灯杆、电杆上 | 墙：单面；杆：单面 / 双面 | 依附物、杆径、离墙距离 |
| 电子站牌立杆 | 带屏或灯箱的厚箱体立杆，有底座 | 单面 / 双面 | 总高、箱体厚、底座高、屏幕高 |

现有数据里的"候车亭灯箱"归候车亭（挂在背板灯箱），"电子站牌立杆"归电子站牌立杆。

### 1.3 尺寸依据

北京地方标准 DB11/T 650-2009《公共汽电车站台规范》：

- 候车亭顶篷篷缘最低点离站台地面不小于 2.5 m（5.1.3），顶篷宽度不宜小于 1.5 m（5.1.4）。
- 多块站牌竖向排列时，最上面一块的顶边离地不大于 2.2 m，最下面一块的底边离地不小于 0.4 m（5.2.3）。

这些数值用作参数默认值和预设预览里的参考线，不做强制校验（各地标准不同）。深圳的首末站站名牌指引把站名牌分为落地式和附着式，与第 1.2 节的"附着式"一致。

### 1.4 模型格式

| 格式 | 适合 | 结论 |
|---|---|---|
| SVG | 2D 矢量图，浏览器原生，可由代码生成 | 2D 立面用它（由参数生成，不存文件） |
| glTF 2.0 / GLB | Web 上 3D 的标准交付格式；three.js、model-viewer 原生支持，可压缩 | 将来需要上传真实模型时用它；M7 不做上传 |
| OBJ | 只有几何和简单材质，没有层级和动画 | 不选 |
| FBX | 私有格式，Web 端要转换 | 不选 |
| STL | 只有三角面，没有颜色材质，面向 3D 打印 | 不选 |
| IFC（BIM） | 建筑信息模型，信息全但很重 | 不选 |

### 1.5 结论（Q81–Q84）

站架都是"柱 + 牌 + 棚 + 箱"的简单几何，参数一填就能确定。所以每个站架类型只存"结构形式 + 参数"，2D 立面与 3D 场景都由前端按参数实时生成：2D 与 3D 同源，牌面按毫米与结构对齐，不需要会建模，也不用传文件（Q81）。编排仍在 2D 立面里做，3D 是只读预览（Q82）。六种形式都做（Q83）。站架类型取代字典里的这一类，站架模板保留为"站架类型 + 站牌结构"（Q84）。理由与后果写进 ADR 0004。

- [深圳市公交首末站站名牌设置指引（深圳市交通运输局）](https://jtys.sz.gov.cn/attachment/0/948/948902/9583254.pdf)

## 3. 数据与迁移

### 3.1 结构形式与参数

参数全部以毫米为单位，存成 JSON，按形式用 zod 判别联合校验（`packages/shared/src/shelf-type.ts`）。下表给出默认值与范围（**默认，可改**）。

**通用（所有形式）：**

| 参数 | 含义 | 默认 | 范围 |
|---|---|---|---|
| `mountBottom` | 牌面下沿离地 | 800 | 0–3000 |
| `orientation` | `parallel` 牌面平行路缘、正面朝站台；`perpendicular` 牌面垂直路缘、正面朝来车方向 | `parallel` | — |

**按形式：**

| 形式（`form`） | 参数 | 默认 |
|---|---|---|
| 单立柱 `singlePost` | `postHeight` 柱高；`postDiameter` 柱径；`mount` 挂法 `center` 居中 / `flag` 旗式；`sides` 1 或 2 | 3000；89；`center`；1 |
| 双立柱 `doublePost` | `postHeight`；`postDiameter`；`postInset` 柱中心到牌组边缘的距离（负数表示柱在牌外侧）；`sides` | 2600；76；100；2 |
| 候车亭 `shelter` | `length` 长度；`depth` 顶棚进深；`canopyBottom` 顶棚下沿高；`canopyThickness` 顶棚厚；`posts` 立柱数（2–8）；`mount` `back` 背板 / `end` 端板；`backPanel` 有无背板；`sides` 1 或 2（亭内 / 亭外） | 6000；1600；2500；150；3；`back`；是；1 |
| 多面柱 `totem` | `faces` 面数（3–6，对应 A 起的各面）；`height` 柱高；`margin` 牌组两侧留边；`baseHeight` 底座高 | 3；3000；60；200 |
| 附着式 `attached` | `host` `wall` 墙 / `pole` 杆；`poleDiameter` 杆径；`poleHeight` 杆高；`standoff` 牌面离墙或杆的距离；`sides`（墙只能 1） | `wall`；160；6000；50；1 |
| 电子站牌立杆 `ePost` | `height` 总高；`boxDepth` 箱体厚；`baseHeight` 底座高；`screenHeight` 屏幕高（0 表示无屏，屏在牌组上方）；`sides` | 2800；160；300；500；2 |

每种形式的面由参数决定：`sides` 为 1 时只有正面，为 2 时有正面、背面；候车亭的正面是亭内、背面是亭外；多面柱是 A 起的 `faces` 个面。

### 3.2 表结构

```prisma
enum ShelfForm {
  singlePost
  doublePost
  shelter
  totem
  attached
  ePost
}

/// 站架类型（M7）：结构形式 + 参数，2D 立面与 3D 由前端按参数生成。
/// 改参数立即影响所有引用它的站架的展示，不进站牌集快照（BR-23）
model ShelfType {
  id          String          @id @default(uuid(7)) @db.Uuid
  name        String          @unique
  form        ShelfForm
  /// 按 form 校验，见 shared/shelf-type.ts
  params      Json
  desc        String          @default("")
  /// 迁移时按名称识别出的形式，保存一次后清除
  needsReview Boolean         @default(false)
  createdAt   DateTime        @default(now())
  updatedAt   DateTime        @updatedAt
  shelves     Shelf[]
  templates   ShelfTemplate[]

  @@index([updatedAt, id])
}
```

- `Shelf.type`、`ShelfTemplate.type` 改为引用 `ShelfType`（`onDelete: Restrict`），字段名 `typeId` 不变。
- `DictItem` 去掉 `shelves`、`shelfTemplates` 两个关系；`DictCategory` 去掉 `shelfType`；`TombstoneType` 加 `shelfType`。
- `name` 在迁移里用 `COLLATE "zh-x-icu"`，与其他名称字段一致。

### 3.3 迁移

一个迁移文件完成，顺序如下：

1. 建枚举 `ShelfForm` 与表 `ShelfType`。
2. 把 `DictItem` 里 `category = 'shelfType'` 的行插入 `ShelfType`，`id`、`name`、`createdAt`、`updatedAt` 原样保留，`needsReview = true`。形式按名称识别（规则按顺序匹配，先中先得）：

   | 名称包含 | 形式 | 附带参数 |
   |---|---|---|
   | 候车亭、雨棚、亭 | 候车亭 | 含"端"时 `mount = end` |
   | 图腾、多面、三面、四面、五面、六面 | 多面柱 | 面数取名称中的数字，没有时取 3 |
   | 电子 | 电子站牌立杆 | — |
   | 挂墙、附墙、壁挂、附着、挂杆、附杆 | 附着式 | 含"杆"时 `host = pole` |
   | 单立柱、单柱、单杆 | 单立柱 | — |
   | 其他 | 双立柱 | — |

   其余参数取第 3.1 节默认值。`sides`：名称含"双面"，或引用它的站架里有背面站牌时取 2，否则取 1（附着式挂墙固定 1）。多面柱的 `faces` 再与站牌实际用到的 A–F 面数取较大值。
3. 删除 `Shelf`、`ShelfTemplate` 指向 `DictItem` 的外键，改建指向 `ShelfType` 的外键。ID 相同，不改数据。
4. 删除 `DictItem` 里站架类型这一类的行。
5. 重建 `DictCategory`，去掉 `shelfType`；`TombstoneType` 增加 `shelfType`。

识别规则在 `packages/shared` 里另写一份 TypeScript（`guessShelfForm`），种子数据用它，测试用同一组用例同时核对 SQL 与 TypeScript 的结果。迁移写出的参数必须能通过 zod 校验。

### 3.4 内部接口

| 接口 | 说明 |
|---|---|
| `GET /api/shelf-types` | 全部站架类型：`id, name, form, params, desc, needsReview, shelfCount, templateCount, updatedAt`；按名称拼音序 |
| `POST /api/shelf-types` | 新建；名称唯一 |
| `PATCH /api/shelf-types/:id` | 改名称、形式、参数、说明；保存即清除 `needsReview` |
| `DELETE /api/shelf-types/:id` | 被站架或模板引用时返回 409 并带引用数（BR-12）；删除时写 `shelfType` 墓碑 |

- 站牌集保存、站架模板保存改为校验 `typeId` 存在于 `ShelfType`（`sign-set.service.ts`、`shelf-template.ts` 里原来查字典的地方）。
- 字典接口不再接受 `shelfType` 类别。
- 站牌集列表的"站架类型"筛选参数名不变（`shelfTypeIds`）。

### 3.5 只读 API

- 新增 `GET /api/v1/shelf-types`：`id, name, form, params, desc, createdAt, changedAt`；与其他列表一样按（`changedAt`，`id`）游标分页，支持 `updatedSince`。
- `GET /api/v1/dict-items` 向后兼容：仍返回 `category = shelfType` 的行，数据来自 `ShelfType`。两个来源各按（`updatedAt`，`id`）取一页，合并后再截取一页，游标照常有效。OpenAPI 里把这个类别标为过时，指向 `shelf-types`（**默认，可改**）。
- 站牌集、站架模板里的 `type` 增加 `form` 字段，原有的 `{ id, name }` 不变。
- 已删除对象增加 `shelfType` 类型；迁移前删除的站架类型仍以 `dictItem` 记录。
- 改站架类型的参数和改名一样，不算引用方站牌集"有变化"。

## 4. 站架模型（S3）

### 4.1 一个模块，两种画法

`apps/web/src/shelf-model/` 只导出一个纯函数，不依赖 React：

```ts
buildShelfModel(
  type: { form: ShelfForm; params: ShelfParams },
  faces: { face: BoardFace; boards: { id: string; width: number; height: number }[] }[],
  opts?: { ghost?: boolean },
): ShelfModel

interface ShelfModel {
  faces: {
    face: BoardFace | 'other'
    label: string            // 正面、背面、亭内、A 面……；不在类型里的面归"其他面"
    width: number            // 毫米，这一面立面的总宽
    height: number
    view: Prim2D[]           // 立柱、顶棚、背板、柱身、底座、箱体、屏幕、墙、地面线、折断号
    mounts: { boardId: string; x: number; y: number; w: number; h: number }[]
    toShelf: Matrix4Like     // 面内坐标 → 站架坐标（3D 用）
  }[]
  parts: Part3D[]            // box / cylinder / prism，站架坐标，毫米
  footprint: { width: number; depth: number }
  warnings: string[]         // 牌组超出候车亭长度、站牌所在的面不属于这个类型等
}
```

- 2D 立面画每个面的 `view`，再把站牌放到 `mounts` 的位置；3D 把 `parts` 画成网格，站牌按 `mounts` 经 `toShelf` 放上去。
- 坐标约定：毫米；x 沿路缘、从站台看从左到右；y 向上；z 指向车行道。
- 结构尺寸跟着牌组走：
  - 双立柱的柱子在牌组两端，按 `postInset` 内收。
  - 候车亭长度不足以放下牌组时自动加长到牌组宽 + 600，并给出提示。
  - 多面柱每面宽度为该面牌组宽 + 2 × `margin`，取各面最大值。
  - 挂墙的墙面比牌组宽 400。
  - 电子站牌箱体比牌组宽 120，屏幕在牌组上方。
- 站牌所在的面不属于这个类型时（例如改了站架类型），这些站牌归入"其他面"，不画结构，并给出提示。不删除、不阻止保存。
- 无实物站架（`ghost`）照常算几何，由画法决定虚线或半透明。
- 同一输入总是得到同一输出，便于测试和缓存。

### 4.2 立面比例

- 比例仍按最高站牌分紧凑、标准、大三档（不变），结构按同一比例画实际尺寸。
- 牌面下方的柱身超过 1000 mm 时画折断号，压缩到 1000 mm，避免立面过高（**默认，可改**）。

### 11.3 偏离计划与实施中定的小决定

1. **坐标约定**：计划写"z 指向车行道"，与"x 从站台看从左到右、y 向上"合起来是左手系；实现取右手系 z 指向站台（车行道在 −z），与 three.js 一致。只影响内部代码。
2. **3D 依赖**：`@react-three/drei` 在两个 npm 镜像上都装不下来（依赖 `glsl-noise`、`@monogrid/gainmap-js` 等 ECONNRESET），而计划里它只用来提供 OrbitControls，改用 three 自带的 `three/examples/jsm/controls/OrbitControls.js`。另外 R3F 的 `<Canvas>` 会 `extend(THREE)` 把整个 three 打进包里，3D 分包 gzip 257 KB 超预算；改用 R3F 的 `createRoot` 自己挂载、只注册用到的 10 个类（`gl-canvas.tsx`），降到 196 KB。版本：`three` 0.186.1、`@react-three/fiber` 9.8.1、`@types/three` 0.186.0。
3. **候车亭的面**：背板在靠站台一侧，亭内（正面）朝车行道，所以 3D 默认视角（从站台一侧斜看）看到的是背板外侧，亭内的灯箱要点"背面"视角看。端板灯箱的两面垂直路缘。
4. **候车亭预设与种子的牌面下沿取 400 mm**：灯箱约 2 m 高，按通用默认 800 mm 会高出 2.5 m 的顶棚下沿（立面与属性卡会给出提示）。迁移来的类型仍按计划取 800，留给核对。
5. **空的面也按完整结构画**：双面类型只在正面挂牌时，背面照样画出同宽的结构，可以直接在背面加站牌；代价是立面比原来宽。
6. **多面柱面数**：迁移与 `guessShelfForm` 取"用到的最大 A–F 面"（用到 A、D 时为 4 面），保证已有站牌都落在类型的面里。
7. **PATCH 提交完整内容**（名称、说明、形式、参数），前端编辑页本来就整体保存。
8. **3D 工具条多一个"回到立面"按钮**（计划里只在没有 WebGL 时有），e2e 用它切回。
9. **编辑器里 3D 视角条放在左上角**：属性卡浮在右上角，选中站牌后会盖住视角条和"回到立面"（e2e 发现）。站架类型页的小预览没有属性卡，视角条仍在右上角。

### 11.5 没做 / 留意

- 手动看过：双立柱、单立柱、候车亭、三面图腾柱、挂墙、电子站牌立杆（无实物虚线）的立面；双立柱 + 候车亭的 3D（正面、背面、点选）、图腾柱 3D 预览；深色模式下的立面与 3D（背景、牌面贴图、顶棚随令牌变化）；开发库副本迁移后四个类型都标"待核对"、形式符合预期。没逐个在 3D 里看单立柱旗式、挂杆、端板灯箱、垂直路缘几种预设（模型单元测试覆盖了它们的几何）。
- 顺带修正：`apps/server/test/design-scale.ts`（M5 的设计规模造数）里 `abs(hashtext(...))` 是 int4，`h + n * 613` 在哈希接近 2^31 时溢出，每次运行约 5% 的概率让 `assist-perf.test.ts` 的 4 个用例在造数阶段失败（本次验收时遇到一次）；改为先转 bigint。
- 部署：`deploy/backup/backup.sh` 的表计数按 `information_schema` 动态列出，新表自动包含，不用改。
- 内置浏览器面板不在前台时 `requestAnimationFrame` 不触发，按需渲染的 3D 一帧都不画；这是预览环境的现象，不是代码问题。
