## 2. 领域规则

### 2.1 途经与编排

- **途经**：运营中线路的某个走向，在站序中第 N 次经过本站点。以（走向 ID，第几次途经）定位（BR-05）。第几次途经按站序实时计算，和 M2 一致。
- **编排放置**：一次途经在本站有三种情况（BR-06）：
  - 隐藏：只有一条"隐藏"编排。
  - 已放置：一条或多条放置编排，每块站牌最多一条。
  - 待编排：没有任何编排。
- **放置目标**（BR-07）：
  - 整版站牌：编排直接放在站牌上，带顺序。
  - 分片站牌：编排只能放在线路插片上，每个线路插片最多一条。
  - 非线路插片：不放编排。
- **状态**（需求 5.5.2），实时计算：
  - 已编排：有放置编排，且走向仍经过本站。
  - 隐藏：有隐藏编排，且走向仍经过本站。
  - 待编排：途经存在，但没有任何编排。
  - 失效：有编排，但（走向，第几次途经）已不是当前的途经。原因可能是站序调整、线路停运，或环线少经过了一次。
- **失效编排**：保留在原位，以失效样式显示。可以单条移除、一键清理，也可以在整版站牌内调整顺序。不能把它放到新的站牌或插片上，也不能复制或隐藏，因为它已经不经过本站。服务端也校验这一点：失效的（走向，途经）只能出现在保存前它已经在的位置上。**默认，可改**
- **走向重新经过本站时，失效编排自动恢复**，例如线路恢复运营、站序改回来。
- **"第几次途经"按位置对应。** 环线原本两次经过某站，删掉第 1 次之后，原来的第 2 次变成第 1 次，沿用原第 1 次的编排；原第 2 次的编排变成失效。这是 Q16"不用路径站 ID"的自然结果，在编辑器的失效提示里写明"可能因为站序调整"。

### 2.2 结构

| 对象 | 规则 |
|---|---|
| 站架 | 编号 1–15，站牌集内唯一，以中文数字显示（"一号架"）；站架类型引用字典；排列顺序即立面上从左到右的顺序 |
| 站牌 | 编号 1–90，站牌集内唯一（"三号牌"）；面：正面、背面、A–F 面；整版或分片；宽、高为正整数毫米，上限 10000 **默认，可改** |
| 插片 | 编号在所在站牌内唯一；线路插片或非线路插片（非线路说明必填）；宽、高同站牌 |

- **新增站架、站牌、插片的编号**：自动取下一个可用值，编号用尽时不能再加。
- **站牌在整版与分片之间切换：** 其上编排删除。切到分片时生成 1 个与牌面同尺寸的线路插片，可以再增删。**默认，可改**
- **删除站架、站牌、插片，或重新套用模板（替换站架下的站牌与插片）：** 其上编排删除。该途经在别处还有放置就保持已编排，否则回到待编排。
- **线路插片改成非线路插片：** 插片上的编排删除。

### 2.3 保存前的提示

这些情况可以保存，但要先确认（需求 5.5.3）。**默认，可改**

- 分片站牌没有任何线路插片。
- 站架下没有站牌。

### 2.4 自动排序

整版站牌内的自动排序（AC-15）：

- 先按线路名排序（5.5.6，`compareLineName`）。
- 线路名相同按走向顺序：上行、下行、内环、外环、单向、环线。
- 走向也相同按第几次途经。
- 失效编排一起排序，不删除（BR-15）。

托盘里的待编排、隐藏用同样的顺序。

## 3. 后端

### 3.1 数据表

| 表 | 字段 | 约束 |
|---|---|---|
| `Shelf` 站架 | 站牌集、站架类型（字典，Restrict）、编号、名称、说明、无实物站架、材质说明、排列顺序 | （站牌集，编号）唯一；随站牌集级联删除 |
| `Board` 站牌 | 站架、站牌集（冗余，用于编号唯一）、面、类型、编号、宽、高、备注、在站架内的顺序 | （站牌集，编号）唯一；随站架级联删除 |
| `Slot` 插片 | 站牌、编号、类型、非线路说明、宽、高、顺序 | （站牌，编号）唯一；随站牌级联删除 |
| `Schedule` 线路编排 | 站牌集、走向（Restrict）、第几次途经、放置方式（站牌 / 插片 / 隐藏）、站牌、插片、顺序 | 见下 |
| `ShelfTemplate` 站架模板 | 名称、站架类型（字典，Restrict）、说明、无实物站架、示意图（上传文件，可空）、站牌结构（JSONB） | （站架类型，名称）唯一 **默认，可改** |

**`Schedule` 的约束：**

- 放在插片上的编排同时记下插片所在的站牌，这样"同一块站牌最多一次"对整版、分片一视同仁。
- 部分唯一索引，由迁移里手写 SQL（同 M1 的 `COLLATE "zh-x-icu"`）：
  - 每个插片最多一条：`(slotId) WHERE slotId IS NOT NULL`。
  - 同一途经在同一块站牌最多一次：`(signSetId, routeId, pass, boardId) WHERE boardId IS NOT NULL`。
  - 同一途经最多一条隐藏：`(signSetId, routeId, pass) WHERE placement = 'hidden'`。
- 隐藏与放置互斥、编排不能放在非线路插片上：由服务端校验。
- **走向外键用 Restrict。** 删除走向前必须先经过 `RouteRemovalHook` 删除编排，否则数据库报错。这样 BR-10 的连带快照不会被漏掉。**默认，可改**
- 站牌集、站牌、插片的外键用 Cascade。站点删除时，站牌集和全部结构、编排一起删除。

站架模板的结构不会被别处引用，所以整块存成 JSONB：`boards: { face, kind, width, height, remark, slots: { no, kind, note, width, height }[] }[]`。站架和模板之间不保留关联（BR-14）。

### 3.2 编排状态的计算

放在一个 `SignSetStatusService` 里，都是原生 SQL（`$queryRaw`），不建缓存（BR-08）。

- **某站点的途经：**
  1. 从路径站里取出这个站点、且所属线路运营中的行。
  2. 按走向分组，按序号用 `row_number()` 编号，得到第几次途经。
  3. 带上线路名、走向、终点站名（走向末站），以及该站在本走向出现的总次数。
- **一个或多个站牌集的计数：**
  1. 所有运营中线路的途经，作为 CTE。
  2. 编排按（站牌集，走向，途经）去重，作为另一个 CTE。
  3. 两者做全外连接，得出每个站牌集的待编排数、失效数、已编排数、隐藏数。
- 站牌集列表、工作台、站点详情都用这一套。前端编辑器拿到途经清单后，用共享包里同样规则的 `poolOf` 实时算状态，保证改草稿时计数即时变化。

**性能：** 按设计上限算（站点 2 万、线路 3000、站架 5 万、站牌 10 万），途经约 18 万行，一次窗口函数加聚合就能算完。站牌集列表包括"只看待处理"筛选，要求 1 秒内（需求 7.1），用性能测试守住。

### 3.3 站牌集快照（`SignSetSnapshotV1` 填充内容）

M1 已定义的顶层外形不变，只把 `shelves`、`schedules` 的元素类型补全。站牌嵌在站架里，不另加顶层键：M1、M2 存的空站牌集快照是 `shelves: []`、`schedules: []`，加了新键会让空站牌集第一次原样保存时哈希不同，产生假修改。

```ts
{
  schema: 1,
  stop: Ref,                // 名称写"站名（方位）"
  reminder: string,
  shelves: { id, no, type: Ref, name, desc, noPhysical, material,
             boards: { id, no, face, kind, width, height, remark,
                       slots: { id, no, kind, note, width, height }[] }[] }[],    // 按排列顺序、站架内顺序
  schedules: { id: `${routeId}#${pass}`, route: Ref /* "K1路 上行" */, pass,
               hidden: boolean,
               places: { boardId, slotId: string | null, order: number | null }[] }[]  // 按 id 排序
}
```

- **站架、站牌按显示顺序排列。** 位置变化是真实修改，差异里显示"移动"。
- **编排按途经归组，每次途经一条，按 id 排序，`places` 作为集合。** 线路改名会改变按名称排出的顺序；按 id 排序后，线路改名不会让下次保存产生假修改。引用对象规范化后只留 ID，站点改名、线路改名、字典改名都不改变哈希。**默认，可改**
- **规范化选项：** `SIGN_SET_NORMALIZE = { sets: ['schedules.places'] }`，在 `SnapshotService` 的 `NORMALIZE` 表里替换现在的 `{}`。
- **差异规格：**
  - 温馨提示。
  - 站架：列表，只比较站架自身字段，显示"一号架 · 双立柱站架"。
  - 站牌：列表，从各站架摊平，显示"三号牌"，插片改动算这块牌"修改"。
  - 线路编排：列表，显示"K1路 上行"，第 2 次途经起加"（第 2 次）"。

  为此 `DiffField` 的列表项加两个可选函数：`items(snapshot)` 取出要比较的数组（摊平站牌、去掉站架里的站牌），`labelOf(item)` 生成显示名（现在的 `labelPath` 不够用）。
- **派生信息不进快照：** 状态、途经总次数、终点站（需求 5.9）。

### 3.4 接口

| 接口 | 说明 |
|---|---|
| `GET /api/sign-sets` | 列表。筛选：站点名称 `q`、街道 `streetId`、路段 `roadId`、经过线路 `lineIds`、站架类型 `shelfTypeIds`、站牌尺寸 `boardSize`（如 `1200x1800`）、只看待处理 `pending=1`。分页。排序：默认站名拼音序再方位，可选待处理数、最近修改。每行带经过线路、市区街道、路段、站架数与类型、站牌数与尺寸、待编排数、失效数、最近修改时间 |
| `GET /api/sign-sets/board-sizes` | 已有的站牌尺寸，供筛选下拉 |
| `GET /api/sign-sets/summary` | 工作台用：待处理站牌集数、待编排总数、失效总数 |
| `GET /api/stops/:stopId/sign-set` | 编辑器与预览用：站点（名称、方位）、站牌集（rev、温馨提示、站架、站牌、插片、编排）、当前途经清单、计数、快照数 |
| `PUT /api/sign-sets/:id` | 整个站牌集一次保存，带 `rev`；冲突返回 409 并带最新内容；没有变化返回 `changed: false`；校验失败返回 400 并逐条列出问题 |
| `GET /api/export/sign-sets` | 站牌集导出，筛选同列表 |
| `GET /api/lines/:id/impact?kinds=` | 停运、恢复、删除、改模式的确认弹窗用：经过的站点数、受影响的站牌集数、编排数；`kinds` 只统计将删除的走向（AC-16） |
| `GET /api/snapshots/recent?limit=20` | 工作台"最近修改"：每个对象只取最近一份快照，按时间倒序；带对象是否还存在，站牌集另带所属站点 ID |
| `GET/POST/PUT/DELETE /api/shelf-templates` | 站架模板；列表按站架类型分组；随时可删除 |

**保存的做法：**

- 前端为新建的站架、站牌、插片生成 UUID（`crypto.randomUUID()`），已有的沿用原 ID。服务端在事务里整体替换：先删掉该站牌集的全部编排和站架（站架级联到站牌、插片），再按提交内容重建。这样 ID 稳定，快照不出现假差异。提交里出现属于别的站牌集的 ID 时拒绝。**默认，可改**
- 有效修改判定沿用 M1：按条件更新 `rev`，重建后生成快照内容；与上一份哈希相同就抛 `NoChange` 回滚整个事务。
- **服务端校验：**
  - 第 2.2 节的编号、尺寸、类型规则。
  - BR-06、BR-07。
  - 编排引用的走向存在。
  - 2.1 节失效编排的限制。
  - 新放置的途经必须是当前途经。如果线路在编辑期间刚停运，返回"K1路 上行已不经过本站（可能刚停运或改了站序），请刷新后重新编排"。

### 3.5 连带处理（`RouteRemovalHook` 的 M3 实现）

`SignSetRouteRemovalHook` 替换 `NoopRouteRemovalHook`，线路服务不用改。

- **`onRoutesRemoved(tx, { routeIds, note })`：**
  1. 找出这些走向上有编排的站牌集。
  2. 分批读出各站牌集删除编排前的内容。
  3. 删除这些编排，给站牌集的 `rev` 加一（已打开的编辑器保存时会收到冲突提示）。
  4. 每个站牌集存一份"连带修改"快照，说明沿用线路服务传入的文字，如"删除线路 K1路，连带移除编排"。

  删线路、改模式、线路导入改模式三个入口都已在 M2 里调用它。
- **`countAffected(routeIds)`：** 返回受影响的站牌集数，删除检查继续用。`/impact` 另外返回编排数。
- **停运、恢复不经过这个接口。** 编排保留，状态实时变为失效或恢复（BR-09）；站牌集不生成快照（AC-05）。

### 3.6 站牌集导出

按需求 5.11 的四个 sheet：

| sheet | 列 |
|---|---|
| 站架 | 站名、方位、站架编号、站架类型、名称、说明、无实物站架、材质说明、排列顺序 |
| 站牌 | 站名、方位、站架编号、站牌编号、面、类型、宽、高、备注 |
| 插片 | 站名、方位、站牌编号、插片编号、类型、非线路说明、宽、高 |
| 线路编排 | 站名、方位、线路名、走向、第几次途经、站牌编号、插片编号、顺序、状态 |

- 状态只有已编排、隐藏、失效。待编排没有编排行，不导出。
- 编号导出为阿拉伯数字整数，方便将来回导。**默认，可改**
- ExcelJS 流式写出；文件名形如 `站牌集_2026-10-28.xlsx`。

### 3.7 其他改动

- **站点详情：** `signSet` 计数改为真实值。
- **站点删除：** 站牌集的"删除"快照存完整内容。
- **站点导入新建站牌集：** 仍存空站牌集快照。
- **字典删除检查：** 站架类型被站架或站架模板引用时不能删除，并列出引用方（BR-12）。

  - 3～4 个站架模板，来自原型 `SHELF_TEMPLATES`。
  - 5～6 个站点的站牌集：覆盖四种状态，包括整版、分片、非线路插片、环线两次途经。
  - 这些站牌集的快照。

### 4.1 立面组件（`components/gt/elevation/`）

编辑器、预览抽屉、站点详情、站架模板编辑器共用，从原型 `EditorElevation.tsx` 和 `parts.tsx` 按正式规范重写。

- **站架排布：** 从左到右排开，按容器宽度自动折行。比例分紧凑、标准、大三档，最高一块牌对应 230 / 320 / 430px，选择记在本浏览器。
- **站架的画法：** 站架类型名称含"候车亭"时画顶棚，其余画立柱；地面线表示安装方式；下方标注编号、类型与名称。无实物站架画成虚线轮廓。站架类型是可改名的字典，按名称判断最省事，以后需要再给字典项加"样式"。**默认，可改**
- **站牌的画法：**
  - 浅金属渐变边框。
  - 墨绿牌头：编号、面、类型与线路数。
  - 线路行用虚线分隔。行内容按牌面像素宽度分三级：窄只显示线路牌与走向；中加终点站；宽再加序号与"开往"。
- **插片：** 嵌入面板，左上角是墨绿号码小标签；非线路插片用斜纹并显示说明。
- **编排状态的样式：** 失效编排是陶土色加删除线。停运线路的编排失效时，线路牌用停运样式。
- **两种模式：** 只读模式只画；编辑模式提供放置目标、选中与菜单。

### 4.2 站牌集编辑器

**草稿模型放共享包** `packages/shared/src/sign-set.ts`。它由原型 `model.ts` 改写成纯函数，前端用于编辑，服务端复用其中的校验，包括：

- 放到站牌、放到插片、隐藏、取消隐藏、移除、复制。
- 排序、自动排序、清理失效。
- 增删改站架、站牌、插片；套用、重新套用模板。
- `poolOf` 状态计算，以及保存前提示。

**版式**（需求 5.5.3）：

1. **顶部：** 返回、站名与方位章、待编排和失效计数、修改历史按钮、撤销修改、保存。
2. **工具条：**
   - 比例三档。
   - 添加站架：空白，或从模板选一个或多个。
   - "清理 N 条失效编排"。
   - 托盘收起、展开。
3. **立面（主区）：** 编辑模式的立面组件。
4. **线路托盘（下方）：**
   - 待编排区：每条显示线路牌、走向、开往；环线两次途经各一条，标"第 1 次""第 2 次"（AC-08）。
   - 隐藏区：虚线投放区。
   - 托盘里不重复列出已编排的线路。
5. **属性卡：** 选中站架、站牌或插片时在右上角浮出，编辑其字段。站架卡里有"重新套用模板"和删除；站牌卡里有类型切换、添加插片和删除。
6. **温馨提示：** 立面上方一条可展开的便签。

**拖放**（dnd-kit，沿用原型的 id 约定 `pool:` `sch:` `board:` `slot:` `hidden` `pool`）：

| 拖法 | 结果 |
|---|---|
| 待编排 → 站牌或插片 | 放置 |
| 站牌上的线路 → 另一块站牌 | 移动 |
| 站牌上的线路 → 待编排区 | 移除这一处编排 |
| 拖进隐藏区 | 隐藏，同时移除该途经在本站的全部放置 |
| 隐藏区 → 待编排区 | 取消隐藏 |
| 整版站牌内拖动 | 排序 |
| 插片已有线路时再放一条 | 原线路回到待编排，并提示 |

**每个拖拽都有不拖拽的替代**（F-COM-08）：

- 托盘条目、站牌上的线路行都有菜单："放到…"（选择目标站牌或插片）、"复制到…"、"隐藏"、"移出本牌"、"取消隐藏"。
- 整版站牌内可用 Alt+↑/↓ 调整顺序。
- 选中整版站牌后，可用"自动排序"。

**撤销：**

- "撤销修改"放弃全部未保存内容，需要确认。
- 另加 Ctrl+Z / Ctrl+Shift+Z 逐步撤销、重做草稿操作。草稿是不可变对象，保存一个历史栈即可，代价很小，拖错时很省事。**默认，可改**

**保存：**

- 整页一次保存。有 2.3 节的情况时，先弹窗列出并确认。
- 成功后显示印章对勾；没有变化时提示"内容没有变化，没有生成修改快照"。
- 未保存拦截沿用站点表单的做法。
- 冲突时弹出 M1 的冲突弹窗，显示最新内容与差异，可以重新载入。

### 4.3 交互细节

- 失效编排拖到站牌或插片上时提示："这条线路已不经过本站，不能再放到别的站牌上"。
- 重新套用模板前确认，写明"该站架下的站牌与插片将被替换，其上 N 条编排回到待编排"。
- 删除结构、切换类型、重新套用模板导致编排被移除时，提示"N 条编排随之移除，相关线路回到待编排"。
- 待编排为 0 时，托盘待编排区显示一句"本站途经都已编排"，配鼠尾草色小对勾。

### 4.4 工作台

**整体：** 原型没有做，按设计语言新做，暖纸底，一屏三块，不做成通用卡片仪表盘。

- **待处理（主角）：**
  - 衬线大号数字显示待处理站牌集数，旁边一枚赭石呼吸点。
  - 下面一行小字："待编排 N 条 · 失效 M 条"。
  - 列出待处理最多的前 5 个站牌集（站名、方位章、状态章），单击进编辑器。
  - "查看全部"进入站牌集列表并带上"只看待处理"筛选。
  - 没有待处理时，换成手绘站牌浮动的空状态和一句"所有站牌集都已编排妥当"。
- **最近修改：**
  - 时间轴样式，沿用修改历史弹窗的轨道与圆点配色，列出最近 20 个对象：对象类型、名称（线路用线路牌）、动作、说明、时间。
  - 单击打开对象：站点、线路进详情，站牌集进编辑器；已删除的对象只能打开修改历史。旁边的历史图标直接打开修改历史弹窗。
  - **默认，可改**
- **快捷新建：** 新建站点、新建线路两个入口。

### 4.5 站架模板

- **列表：** 按站架类型分组。每个模板一张小卡：用立面组件画出缩略结构，配名称、说明、站牌数。
- **编辑：** 左侧属性表，包括名称、站架类型、说明、无实物站架和示意图上传。下方是站牌结构表：每块牌的面、类型、宽、高、备注；分片站牌可展开编辑插片。右侧用立面组件实时预览。
- **删除：** 随时可删，确认弹窗写明"已生成的站架不受影响"（BR-14）。

## 5. 并发、有效修改、快照

- **站牌集带 `rev`，整个站牌集一次保存**（BR-18）。有效修改判定、`NoChange` 回滚沿用 M1。
- **连带修改会给站牌集的 `rev` 加一。** 删线路、改模式之后，已打开的编辑器保存时收到冲突提示。这是预期行为。
- **线路停运、恢复、站序调整都不改站牌集的 `rev`**，因为不扩散（需求 5.9）。编辑器里看到的途经可能已经过时，保存时服务端按当前途经校验，见 3.4 节。
- **走向删除和站牌集保存的先后：** 两者都在事务里。编排的走向外键是 Restrict，所以不会出现指向已删除走向的编排。

## 9. 默认决定汇总（可改）

| # | 决定 | 理由 |
|---|---|---|
| 1 | 失效编排只能保留、排序、移除，不能放到新位置、复制或隐藏；服务端同样校验 | 它已经不经过本站；与原型一致 |
| 2 | 站牌宽高上限 10000 毫米 | 防止误输入；实物站牌远小于此 |
| 3 | 站牌切到分片时生成 1 个与牌面同尺寸的线路插片 | 原型生成 4 个固定尺寸插片，尺寸没有依据；1 个铺满的插片再增删更直观 |
| 4 | 保存前提示两种情况：分片站牌没有线路插片、站架下没有站牌 | 需求举了第一种；第二种同样常是漏填 |
| 5 | 编排的走向外键用 Restrict | 删除走向必须先经过连带处理，BR-10 的快照不会漏 |
| 6 | 站架模板的结构存 JSONB；名称在同一站架类型内唯一；模板不生成快照 | 结构不被引用；套用时复制；快照对象只有三类（需求 5.9） |
| 7 | 编排快照按途经归组、按 id 排序，放置位置作为集合 | 线路改名不改变顺序，不产生假修改；差异按"K1路 上行"一条条显示，好读 |
| 8 | 保存时整体替换站架、站牌、插片、编排，新节点 ID 由前端生成 | 一个站牌集只有几十行，整体替换最简单；ID 稳定，快照不出现假差异 |
| 9 | 站牌集列表是全宽表格，不带地图；默认按站名拼音序 | 需求 F-COM-11 只列站点、线路页面；按站名最好找 |
| 10 | 编号导出为阿拉伯数字 | 将来回导时解析简单 |
| 11 | 编辑器支持 Ctrl+Z 逐步撤销、重做，另有"撤销修改"整体放弃 | 拖错时很省事；草稿本来就是不可变对象 |
| 12 | 工作台"最近修改"列最近 20 个对象，每个对象一行；已删除的对象只能打开历史 | 需求 5.2 没定数量；一个对象连续保存多次时不刷屏 |
| 13 | `/` 跳到工作台 | 需求 5.2 写的是首页 |
| 14 | 新增 `/api/lines/:id/impact` 统一给停运、恢复、删除、改模式的弹窗提供影响数 | 四个弹窗口径一致；改模式时只统计将删除的走向 |
| 15 | 线路导入预览的"将删除的走向"加上受影响的站牌集数 | 和表单里改模式的提示一致 |
| 16 | 站架类型名称含"候车亭"时立面画顶棚 | 不给字典加字段；以后需要再加"样式" |

### 10.3 与计划不同或计划未写明的地方

| 项 | 做法与原因 |
|---|---|
| 编排的 ID | 计划写"已有的沿用原 ID"。站架、站牌、插片照此做；编排每次保存由服务端重建，提交里不带编排 ID。编排的快照 ID 是"走向 ID#第几次途经"，不受影响 |
| 整版站牌内的顺序 | 服务端保存时按提交的顺序规整为 1…n，不要求前端连续 |
| 分片站牌的同一途经 | 同一途经放进同一块分片站牌的另一个插片时视为在牌内移动（保持"同一块站牌最多一次"） |
| `RouteRemovalHook` | 接口新增 `affected(routeIds)`，返回站牌集数与编排数，供 `/impact` 与线路导入预览用；`countAffected` 继续给删除检查用。实现 `SignSetRouteRemovalHook` 在站牌集模块里，`LineModule` 引入该模块并用 `useExisting` 提供注入令牌，线路服务没有改 |
| 列表计数的范围 | "只看待处理"与按待处理数排序先算出筛选范围内全部站牌集的计数（没有筛选条件时直接算全部，省去范围判断）；其余情况只对当前页计数，默认列表约 45 毫秒 |
| 线路导入预览 | `ImportRemovedRoutes` 增加 `signSets`、`schedules` 两个数，预览"将删除的走向"逐条写明 |
| 删除线路弹窗 | 改用 `/impact` 写明站牌集数与编排数；`delete-check` 的 `affectedSignSets` 仍保留 |
| 立面画法 | 计划默认决定 16 只写了候车亭顶棚。另外：站架类型名称含"单立柱"时画一根立柱；无实物站架的立柱与站牌边框画成虚线 |
| 撤销 | 同一个文本字段连续输入合并成一步撤销；保存成功后用服务端返回的内容重置草稿，撤销历史清空 |
| 登录后去向 | 计划只写了 `/` 跳到工作台。登录后默认也进工作台（原来进站点列表）；端到端的登录助手改为等待 `/home`，站点用例改用公共登录助手并先进入站点列表 |
| 导出 | `writeWorkbook` 的行改为也接受异步迭代，四个 sheet 各自每批 500 个站牌集读库，不把全部站牌集放进内存；导出文件名 `站牌集_YYYY-MM-DD.xlsx` |
| 最近修改 | 按时间索引每批 200 份往回读并按对象去重，最多 10 批，不对整张快照表做 `DISTINCT ON`；站牌集带所属站点 ID（来自快照内容），已删除的也能给出 |
| 字典引用 | 站架类型的引用计数包括站架与站架模板；删除检查列出"站牌集""站架模板"两类引用方 |
| 站架模板 | 一个模板最多 20 块站牌；示意图复用上传接口，删除模板不删上传文件 |
| 种子数据 | 站架模板 4 个（原型的 3 个，另加"电子站牌 · 无实物"）；6 个站点的站牌集覆盖四种状态、整版、分片、非线路插片、环线两次途经、停运与站序调整造成的失效，各有一份"修改"快照 |
| 端到端拖拽 | dnd-kit 松手后约 50 毫秒内会拦下点击，`e2e/sign-sets.spec.ts` 的拖拽助手松手后等 120 毫秒再继续 |

### 10.4 已知问题

- 沿用 M1：Prisma 7 的查询解释器在事务里并发取关联数据，pg 8 打印一条弃用警告，功能正常。
- 列表"只看待处理"、按待处理数排序每次都实时计算筛选范围内的全部计数（BR-08 不建缓存）。设计规模下 0.27–0.6 秒，随路径站与编排数量线性增长；超过设计规模时再考虑物化计数。
- 站点详情的"站牌集"一节单独请求一次站牌集内容，比 M2 多一个请求。
- 编辑器在窄窗口（宽度小于约 1100px）下属性卡会压住一部分立面；托盘高度固定。
- 触屏拖拽没有专门测试；"放到…"等菜单可以完成全部放置操作。
- 站牌集的 `updatedSince` 与"因线路变化引起的编排状态变化"按计划留给 M4。
