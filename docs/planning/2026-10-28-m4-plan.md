## 2. API Token

### 2.1 规则

- **格式：** `gt_` 加 32 字节随机数的 base64url，共 46 个字符。库里存 SHA-256 哈希，另存前 10 个字符作为前缀，在列表里辨认。**默认，可改**
  - 不用会话那样的 HMAC（M1 用 `SESSION_SECRET`）。这样更换会话密钥时 Token 不会全部失效。Token 本身熵足够，不需要加盐。
- **名称：** 必填，不超过 50 字，不能重名。
- **吊销：** 直接删除这条记录，下一次请求就返回 401。校验不加缓存。
- **最后使用时间：** 每分钟最多写一次，沿用会话的做法。
- **能访问的范围：**
  - Token 只能访问 `/api/v1/*` 的 GET 请求，用在内部接口 `/api/*` 上一律返回 401。
  - `/api/v1/*` 只认 Token，不认登录 Cookie。
  - 管理 Token 的接口只认登录会话，Token 不能用来创建 Token。
- **安全细节：**
  - 不支持把 Token 放在查询参数里，免得它进入访问日志。
  - 现有日志本来就不记录请求头（M1）。
- **401 的提示：** 统一为"API Token 无效或已吊销"，不区分"不存在"和"已吊销"。
- **修改密码不影响 Token。** Token 给其他系统用，和登录会话无关。

### 2.2 内部接口（登录会话）

| 接口 | 说明 |
|---|---|
| `GET /api/api-tokens` | 列表：名称、前缀、创建时间、最后使用时间；按创建时间倒序 |
| `POST /api/api-tokens` | 新建：`{ name }`。返回内容里带 `token` 明文，只有这一次 |
| `DELETE /api/api-tokens/:id` | 吊销 |

### 2.3 守卫

- 全局 `AuthGuard` 增加一种标记 `@TokenAuth()`。
  - 有这个标记的接口按 `Authorization: Bearer` 校验 Token。
  - 没有标记的接口仍按 Cookie 校验会话。
  - `@Public()` 不变。
- `CsrfGuard` 不用改，因为 `/api/v1` 只有 GET。
- 请求对象上记下当前 Token 的 ID，供以后需要时使用；本期不记录逐次调用日志。

## 3. 只读 API

### 3.1 约定

- **路径与方法：** 前缀 `/api/v1`。只有 GET（HEAD 由框架自动处理）；其他方法返回 404。
- **鉴权：** `Authorization: Bearer gt_…`。
- **字段与格式：**
  - 字段用 camelCase。
  - 时间用 ISO 8601 UTC，带毫秒，如 `2026-10-28T08:00:00.000Z`。
  - 坐标按库里的值原样输出，是高德的 GCJ-02 坐标系。文档里写明。**默认，可改**
- **引用其他对象：** 写成 `{ id, name }`，名称取当前值。被引用对象改名，不算引用方"有变化"（3.4 节）。下游应按 ID 关联，参考数据单独同步。
- **枚举：** 输出代码值，如 `mode: "double"`、`status: "waiting"`。中文名列在 OpenAPI 的说明里。**默认，可改**
- **扩展字段：**
  - 写成 `ext: { [键]: 值 }`，只含启用中的字段。
  - 值的类型：文本、下拉为字符串；数字为数字；日期为 `YYYY-MM-DD`；时间为 `HH:mm`；文本列表为字符串数组。
  - 字段定义从 `/api/v1/ext-fields` 取。
- **错误：** 沿用现有格式 `{ code, message, details }`。
  - 401 `UNAUTHORIZED`。
  - 404 `NOT_FOUND`，已删除的对象也返回 404，下游查已删除列表。
  - 400 `VALIDATION_FAILED`，参数或游标不合法。
- **缓存：** 响应头 `Cache-Control: no-store`；文件除外（3.7 节）。

### 3.2 资源

| 接口 | 内容 |
|---|---|
| `GET /api/v1/stops`、`/stops/{id}` | 站点：名称、方位、英文名、坐标、市区街道、路段、二维码地址、站台设施、维护公司、备注、地标、照片（`{ id, url }`）、扩展字段、`createdAt`、`changedAt` |
| `GET /api/v1/lines`、`/lines/{id}` | 线路：名称、编号、英文名、模式、状态、票制、票价、公交公司、票价体系、扩展字段、走向列表、`changedAt`。每个走向有 ID、走向种类、服务类型、服务时间、间隔、路径站；每个路径站有序号、站点、第几次途经、到站时刻、扩展字段 |
| `GET /api/v1/sign-sets` | 站牌集列表（用于增量同步），每项是完整内容 |
| `GET /api/v1/stops/{stopId}/sign-set` | 按站点查询站牌集（需求 5.12） |
| `GET /api/v1/landmarks`、`/landmarks/{id}` | 地标：名称、类别、位置点（经纬度、辐射半径）、`changedAt` |
| `GET /api/v1/landmark-categories`、`/landmark-categories/{id}` | 地标类别 |
| `GET /api/v1/dict-items?category=` | 字典项，可按七类之一筛选 |
| `GET /api/v1/regions` | 行政区划：级别、名称、上级 ID |
| `GET /api/v1/bus-companies` | 公交公司：名称、英文名、简称、logo（`{ id, url }`）、服务热线 |
| `GET /api/v1/shelf-templates` | 站架模板：名称、站架类型、说明、无实物站架、示意图、站牌结构。**默认，可改**：需求 5.12 的"文件"包括模板示意图，没有这个列表就拿不到它 |
| `GET /api/v1/ext-fields` | 扩展字段定义：归属、键、名称、类型、下拉选项、是否启用、站点字段的显示分区。**默认，可改**：没有定义，下游看不懂 `ext` |
| `GET /api/v1/deleted` | 已删除对象（3.6 节） |
| `GET /api/v1/files/{id}` | 文件（3.7 节） |
| `GET /api/v1/openapi.json`、`/api/v1/docs` | OpenAPI 文档与文档页，不需要 Token（3.8 节） |

**站牌集的内容：**

- **站点：** `stop: { id, name }`。
- **温馨提示：** `reminder`。
- **站架：** 编号、类型、名称、说明、无实物站架、材质说明、排列顺序。
  - 站架下嵌套站牌：编号、面、类型、宽、高、备注。
  - 站牌下嵌套插片：编号、类型、非线路说明、宽、高。
- **途经 `passages`：** 按途经归组，每项包含：
  - `line: { id, name }`、`route: { id, kind }`、`pass`。
  - `status`：`waiting` / `placed` / `hidden` / `invalid`。
  - `places: [{ boardId, slotId, order }]`。
  - 待编排的途经也列出来，`places` 为空。
- **计数：** `counts: { waiting, placed, hidden, invalid }`。
- **时间：** `changedAt`。

下游可以用（走向 ID，站点 ID，第几次途经）把站牌集的途经和线路的路径站对上。

**组装与一致性：**

- 用 M3 已有的 `SignSetService.contents`、`SignSetStatusService.liveKeys` 和 `routeInfos` 批量组装，不逐个查。
- 一页数据在同一个只读事务（REPEATABLE READ）里读出，保证结构和状态一致。

### 3.3 分页与增量同步

- **参数：**
  - `updatedSince`（可选）：只返回 `changedAt` 晚于它的对象。
  - `cursor`（可选）：上一页返回的游标。
  - `limit`：默认 100，最大 500；线路和站牌集内容大，最大 100。
- **排序：** 固定按（`changedAt`，`id`）升序，用游标分页，不用页码。**默认，可改**
  - 页码分页在翻页期间如果有对象被修改，后面的对象整体前移，会漏掉一个。
  - 游标分页里，被修改的对象移到末尾，本轮后面会再读到它。
- **响应：** `{ items, nextCursor, nextUpdatedSince }`。
  - `nextCursor` 为 `null` 表示本轮已取完。
  - 不返回 `total`：游标分页下统计总数代价高，同步也用不到。
- **`nextUpdatedSince`（本轮的"水位"）：**
  - 第一页（不带游标时）计算：取当前时间和"进行中的写事务最早开始时间"里较早的一个，再减 5 秒。
  - 计算方法：`pg_stat_activity` 里本库、`backend_xid` 不为空、不是自己的连接，取 `xact_start` 的最小值。
  - 水位写进游标，后续每一页原样返回。所以本轮任何一页的值都相同。
  - **为什么要这样算：** 导入是一个事务，最长 10 分钟（`import.service.ts` 的 `TX_OPTIONS`）。其中对象的修改时间早于提交时间。如果水位只取"当前时间"，下一轮就会漏掉这些对象。减 5 秒是为了容忍应用和数据库的时钟误差。
- **下游的做法（写进 OpenAPI 说明）：**
  1. 第一次不带 `updatedSince`，翻页取完，记下 `nextUpdatedSince`。
  2. 以后每次带上记下的值，翻页取完，再记下新的值。
  3. 同一轮里同步一次已删除对象。
  4. 会重复取到少量对象，按 ID 覆盖即可。
- **游标格式：** base64url 编码的 `{ 水位, 最后一项的 changedAt, 最后一项的 id }`。解析失败返回 400。
  - 翻页时其余参数要和第一页相同，文档里写明，服务端不校验。

### 3.4 "有变化"的口径（`changedAt`）

| 资源 | `changedAt` 取值 |
|---|---|
| 站点 | `Stop.updatedAt` |
| 线路 | `Line.updatedAt` |
| 站牌集 | 新列 `SignSet.changedAt`，见 3.5 节 |
| 地标 | `Landmark.updatedAt`；位置点随地标一起保存 |
| 地标类别、字典项、行政区划、公交公司、站架模板、扩展字段定义 | 各自的 `updatedAt` |

- **站点、线路直接用 `updatedAt`：** 每次有效修改（表单保存、导入）都会更新这一行（`rev` 加一）。没有变化的保存会回滚，时间不变。
  - 实施时要用测试逐条核对写入路径，不能只改了子表而不碰主行：
    - 线路：只改路径站或到站时刻、改模式删走向、导入修改。
    - 地标：只改位置点。
  - 漏了的路径要显式更新主行。
- **不算"有变化"的情况（写进文档）：**
  - 被引用的对象改名（字典项、区划、公交公司、地标、线路、站点名称）。
  - 扩展字段定义变化，例如停用后输出不再包含该字段。文档建议：改了扩展字段定义后，下游做一次全量同步。
- **原生 SQL 写时间：** 统一用 `now() AT TIME ZONE 'UTC'`。Prisma 的 `DateTime` 列是不带时区的 UTC 时间；数据库会话时区如果不是 UTC，直接写 `now()` 会差 8 小时。
  - 数据库容器保持 UTC，不设 `TZ`。
  - 测试里把会话时区设成 `Asia/Shanghai` 来验证。

### 3.5 站牌集的 `changedAt`

站牌集的对外内容包括结构、编排和各途经的状态。途经由运营中线路的走向站序决定（M3 计划 3.2 节）。所以 `changedAt` 在两种情况下更新：

1. **站牌集自身有快照写入：** 编辑器保存、连带修改都算。在 `SnapshotService.record` 写入快照的同一事务里更新。
2. **线路有快照写入，并且"编排投影"变了：** 包括新建、修改、导入新建、导入修改、删除。
   - **编排投影：** 线路状态，加上每个走向的"种类 + 有序站点 ID 列表"。
     - 由此可以算出每个站点的途经集合：`{ 走向种类#第几次途经 }`。
     - 线路名不在投影里，因为线路改名按 3.4 节不算"有变化"。
   - **线路状态变了**（停运、恢复）：前后两份快照里出现过的站点，它们的站牌集全部更新。
   - **否则：** 只更新途经集合前后不同的站点，包括只出现在一边的站点。
   - **示例：**
     - 走向里加入站点 X：只有 X 的途经变了，只更新 X 的站牌集。环线里 X 的第二次途经同样算在内。
     - 改模式、删走向：受影响的站点更新。
     - 删除线路：前一份快照里的站点全部更新。没有编排、只有待编排的站牌集也包括在内，因为它们的待编排消失了。连带快照只覆盖有编排的站牌集，所以这一条不能省。
     - 只改到站时刻、票价、公交公司：不更新。
   - 计算放在共享包的纯函数里（`passagesByStop(lineSnapshot)`、`touchedStops(prev, next)`），方便单元测试。
   - `SnapshotService.record` 本来就会读上一份快照的内容，前后两份都在手上。更新用一条原生 SQL：按站点 ID 更新 `SignSet`，不碰 `rev` 和 `updatedAt`，不影响已打开的编辑器。
   - 放在 `snapshots` 模块里的一个小服务 `ChangeClock` 中，不用引用站牌集模块，也就没有循环依赖。**默认，可改**
3. **不更新：** 站点改名。站牌集里的 `stop.name` 按 3.4 节属于引用。

**迁移回填：** `SignSet.changedAt = updatedAt`；建（`changedAt`，`id`）索引。下游第一次本来就做全量同步，不需要更精确的回填。

### 3.6 已删除对象

`GET /api/v1/deleted?type=&updatedSince=&cursor=&limit=`。参数名沿用 `updatedSince`，含义是"删除时间晚于它"，这样下游可以复用同一套翻页代码。

**来源：**

| 类型 | 来源 |
|---|---|
| `stop`、`line`、`signSet` | 快照表里动作为"删除"的记录（已有索引 `objectType, action, createdAt`） |
| `landmark`、`landmarkCategory`、`dictItem`、`region`、`busCompany`、`shelfTemplate` | 新表 `Tombstone`（类型、对象 ID、名称、删除时间），在这六处删除时于同一事务写入；永久保留 |

- `type` 可选，不传时返回全部类型。
- **返回内容：** 每项 `{ type, id, name, deletedAt }`。
- **排序与游标：** 按（`deletedAt`，`id`）排序，游标与水位的做法同 3.3 节。
- **两个来源的合并：** 按排序键归并后取一页。

扩展字段定义只能停用，不能删除，所以不在这里。站点删除时它的站牌集也会删除，站牌集已经有"删除"快照（M3），会出现在列表里。

### 3.7 文件

- **新接口：** `GET /api/v1/files/{id}` 用 Token 访问，复用 `UploadService.locate` 和现有下载逻辑。
- **地址格式：** 只读 API 输出里的文件地址统一写成相对路径 `/api/v1/files/{id}`。
- **内部 `/api/uploads/:id`：** 仍然只认登录会话。M1 代码注释写的"M4 起也接受 API Token"改为：Token 用户走 `/api/v1/files`。理由是 `/api/v1` 整体只认 Token，内部接口整体只认会话，规则简单。**默认，可改**
- **缓存头：** `Cache-Control: private, max-age=86400`。文件内容不会变，因为上传后不改、不删。

### 3.8 OpenAPI 与文档页

- **模式定义：** 输出结构和查询参数用 zod 定义在共享包 `packages/shared/src/api-v1.ts`。
- **生成：** 服务端 `src/api-v1/openapi.ts` 按一张接口表（路径、摘要、查询模式、响应模式）生成 OpenAPI 3.1 文档。JSON Schema 用 zod 4 自带的 `z.toJSONSchema`。
  - 不用 `@nestjs/swagger`：它要另写一套 DTO 类和装饰器，和 zod 模式重复。**默认，可改**
- **接入说明：** 写在 `info.description` 里，在文档页显示。内容包括鉴权、分页与增量同步的步骤（3.3 节）、"有变化"的口径（3.4 节）、坐标系、引用与枚举的中文名。
- **文档页：** `/api/v1/docs` 用 `swagger-ui-dist` 的本地静态文件，不走 CDN，内网也能打开。
  - 文档和文档页不需要 Token，因为里面没有业务数据。**默认，可改**
  - 设置的"API Token"页签放一个链接。
- **契约测试：**
  - 每个接口的响应都用对应的 zod 模式严格校验。
  - 检查 OpenAPI 文档里的路径集合与控制器路由一致。

### 3.9 实现结构

- 新模块 `apps/server/src/api-v1/`，按资源拆成几个薄控制器，加 `mappers.ts` 和 `paging.ts`（游标与水位）。
- 列表批量查询，不出现 N+1。
- 站点、线路的输出复用现有的详情加载逻辑，或者快照构造函数里的字段映射，避免两套口径。
- **性能目标：** 都在设计规模下（2 万站点、3000 线路、站架 5 万、站牌 10 万）测，每页 < 1 秒。
  - 站点一页 500 条。
  - 线路一页 100 条。
  - 站牌集一页 100 个。
  - 带最近 `updatedSince` 的增量查询 < 200 毫秒。
  - 已删除对象一页 500 条。

### 3.10 数据库改动（迁移 `…_api_v1`）

- `ApiToken`：名称（唯一）、前缀、哈希（唯一）、创建时间、最后使用时间。
- `Tombstone`：类型、对象 ID、名称、删除时间；建（删除时间，ID）索引。
- `SignSet.changedAt`：带回填，建（`changedAt`，`id`）索引。
- `Stop`、`Line`、`Landmark` 等主表：补（`updatedAt`，`id`）索引。`Stop` 已有 `updatedAt` 索引，改成复合索引。

## 4. Docker 部署

### 4.1 镜像（仓库根目录 `Dockerfile`）

- **多阶段构建，基础镜像 `node:24-bookworm-slim`。** 不用 alpine，避免 Prisma 和 argon2 的 musl 兼容问题。具体小版本实施时选定，记进完成记录。
- **构建阶段：**
  1. 按 `packageManager` 用 corepack 启用 pnpm 11.13.1。
  2. `pnpm install --frozen-lockfile`，再 `pnpm -r build`。
  3. 用 `pnpm deploy` 导出服务端的生产依赖。pnpm 10 起需要 `inject-workspace-packages` 或 `--legacy`，实施时核对。
  4. 复制 `prisma/schema.prisma`、`prisma/migrations`，以及执行 `migrate deploy` 需要的 Prisma CLI 和引擎。
  5. 复制前端 `dist`。
- **运行阶段：**
  - 用户 `node`（非 root）。
  - 目录：`/app` 放服务端，`/app/web` 放前端，`/data/uploads` 放上传文件（挂卷）。
  - 环境变量：`NODE_ENV=production`、`HOST=0.0.0.0`、`PORT=3000`、`WEB_DIST=/app/web`、`UPLOAD_DIR=/data/uploads`。
- **入口 `docker-entrypoint.sh`：** 先 `prisma migrate deploy`，再 `exec node dist/main.js`。
  - 迁移失败时容器退出，日志里有原因。
  - 不自动执行种子数据。
  - 应用容器启动时自动迁移：单机单实例，这样最省事。**默认，可改**
- **健康检查：** `HEALTHCHECK` 用 `node -e "fetch('http://127.0.0.1:3000/api/health')…"`，镜像里没有 curl。
- **`.dockerignore`：**
  - 排除 `.env`、`.git`、`node_modules`、各 `dist`、`uploads`、`backups`、`prototype`、测试产物。
  - **`.env` 必须排除**，否则 `COPY . .` 会把密钥打进镜像。演练脚本会检查镜像里没有它（5.4 节）。
- **镜像不含任何高德变量和密钥。** 全部在运行时通过环境变量传入。
- **镜像标签：** `gentransit:<版本>-<git 短哈希>`，同时打 `latest`。版本取根目录 `package.json`，用构建参数传入。

### 4.2 Compose（仓库根目录 `docker-compose.yml`；`docker-compose.dev.yml` 不变）

|---|---|
| `db` | `postgres:16`（实施时固定小版本）；用户和库名 `gentransit`；密码取 `.env` 的 `POSTGRES_PASSWORD`（缺失时 compose 直接报错）；卷 `gt-db`；健康检查 `pg_isready`；默认不对外暴露端口；不设 `TZ`，保持 UTC（3.4 节） |
| `app` | `build: .`，`image: gentransit:${GT_VERSION:-latest}`；`env_file: .env`；在 `environment` 里覆盖 `DATABASE_URL`（指向 `db`，用 `POSTGRES_PASSWORD` 拼出）、`HOST`、`UPLOAD_DIR`、`WEB_DIST`、`TRUST_PROXY`（默认 `loopback,uniquelocal`）、`BACKUP_DIR=/backups`；卷：`gt-uploads:/data/uploads`、`./backups:/backups:ro`；端口 `${GT_HTTP_PORT:-8080}:3000`；等 `db` 健康后启动 |

  - 容器里，宿主机上的反向代理来自 Docker 网桥地址，不是回环地址。

## 5. 备份与恢复

### 5.1 一份备份的内容

每份备份是 `backups/<YYYYMMDD-HHMMSS>/` 目录，包含：

- **`db.dump`：** `pg_dump -Fc`，自定义格式、压缩。
- **`uploads/`：** 上传目录的完整文件树。
  - 上传文件只增不改不删（M1 起没有删除接口，外键是 Restrict）。所以先导出数据库、再复制文件，文件就一定覆盖数据库里引用的全部文件。
  - 用硬链接做增量：先 `cp -al` 上一份备份的 `uploads/`，再用 `cp -rn` 补上新文件。每份备份都是完整、独立的文件树，但未变化的文件不重复占空间；删除旧备份时，仍被引用的文件不受影响。
  - 不打 tar 包：照片按设计规模可能有几十 GB，每天打一个完整的包，30 天要占几 TB。**默认，可改**
- **`manifest.json`：** 备份时间、应用版本、最后一个已执行的迁移名、`db.dump` 的大小和 SHA-256、上传文件数与总大小、主要表的行数。演练时用来核对。

**备份步骤（`deploy/backup/backup.sh`）：**

1. 写到 `<名称>.partial/`。
2. 导出数据库，用 `pg_restore --list` 自检。
3. 复制上传文件。
4. 写 `manifest.json`。
5. 改名去掉 `.partial`。没改名的不算成功。
6. 更新 `backups/status.json`：最近成功时间、最近尝试时间、最近错误、最新一份的名称和大小。

### 5.2 定时与保留

- **定时：** `backup-loop.sh` 算出到下一个 `BACKUP_TIME` 的秒数，`sleep` 后执行备份。不用 cron，容器更简单。
  - 失败时 1 小时后重试，最多 3 次，每次都写 `status.json`。
- **保留：** 删除名称时间早于 `BACKUP_RETENTION_DAYS` 天的目录，但永远保留最新一份成功的备份；超过 1 天的 `.partial` 目录也删除。
- **手动备份：** `docker compose exec backup /scripts/backup.sh`。手册另给一条升级前备份的命令，备份名带后缀 `-manual`。

### 5.3 恢复（`deploy/restore.sh <备份名>`，在宿主机执行）

1. 要求输入备份名确认；加 `--yes` 可跳过。
2. 停止 `app`。
3. 先给当前数据做一份备份，名称后缀 `-pre-restore`，防止选错备份。**默认，可改**
4. 删库重建，再 `pg_restore --no-owner --exit-on-error`。整库重建，不会留下新版本迁移建的表。
5. 清空上传卷，从备份复制文件树。
6. 核对 `manifest.json` 里的行数和文件数。
7. 启动 `app`。如果备份来自旧版本，入口会自动把迁移补齐。
8. 等健康检查通过。

数据库和文件操作都在 `backup` 容器里执行（用 `docker compose run`，上传卷挂成可写）。宿主机脚本只负责启停和传参，所以 Linux 服务器和本机的 Git Bash 都能运行。

### 5.4 演练（`deploy/drill.sh`，M4 验收用）

在独立的 compose 项目 `gentransit-drill` 里进行：卷和端口都单独一套，不碰正式部署和开发库。

1. **构建镜像，检查镜像内容：** 没有 `.env`；前端文件里没有本机环境变量中高德安全密钥和 Web 服务 Key 的值，只报告是否出现。
2. **启动环境 A，准备数据：**
   - 临时发布 A 的数据库端口，从宿主机执行 `pnpm db:seed --reset` 写入种子数据。
   - 通过接口登录，上传一张图片，新建一个 API Token。
3. **备份 A，记下指纹：**
   - 每张表的行数。
   - 主要表按 ID 排序后的内容 md5。
   - 上传文件清单的 SHA-256。
4. **在 A 上继续改数据：** 删站点、改线路。证明恢复回到的是备份时的状态，不是当前状态。
5. **原地恢复 A：** 指纹与第 3 步相同。
6. **在全新环境 B 上恢复：** 只复制备份目录，模拟换新机器。
   - 指纹相同。
   - 能登录。
   - 第 2 步的 Token 能调用 `/api/v1/stops`（AC-17 在恢复后仍成立）。
   - 用 `/api/v1/files/{id}` 下载的图片字节与原文件相同。
7. **清理：** `down -v` 清掉两个演练环境，输出结论。结论写进本文的完成记录。

在正式服务器上做演练的步骤也写进手册，供部署后由你执行。

### 5.5 备份状态

- **接口：** `GET /api/system/backup`（登录会话）。读取 `BACKUP_DIR/status.json` 和最近几份备份的 `manifest.json`，返回：是否已配置、保留天数、最近成功时间、最近错误、最近 30 天每天的备份是否成功和大小。
- **设置里加"备份"页签（只读）：**
  - 最近一次成功的时间和大小。
  - 30 天日历条：每天一个点，成功为鼠尾草色，缺失留空，失败为陶土色。
  - 恢复命令的提示，以及手册链接。
  - 没有配置 `BACKUP_DIR` 时显示"未配置备份"和手册链接。
- **工作台提醒：** 最近一次成功的备份超过 48 小时，或者最近一次尝试失败时，工作台顶部显示一条赭石色提醒。
- 需求 5.8 的设置项里没有备份。备份悄悄失败几个月才被发现是最常见的事故，所以加上。**默认，可改**

## 6. AC-18：浏览器看不到高德安全密钥与 Web 服务 Key

现状（M1）：

- 安全密钥只在服务端 `/_AMapService` 代理里附加；`/api/config` 只下发 JS Key。
- `e2e/secrets.spec.ts` 已经检查前端构建产物里没有密钥，并检查未登录时 `/api/config` 返回 401。

M4 补三件事：

1. **自动检查（端到端，不依赖外网）：** 新文件 `e2e/amap-secrets.spec.ts`。
   - **另起一个服务端进程：**
     - 安全密钥和 Web 服务 Key 设为每次随机生成的哨兵值。
     - JS Key 留空，地图仍用示意平面。
     - 高德上游指向本地的假服务：它会把收到的请求地址和参数原样写进响应体，模拟上游回显。
     - 上游地址通过新环境变量 `AMAP_UPSTREAM_OVERRIDE` 注入，只在 `NODE_ENV=test` 时生效，生产环境忽略。
     - 把 `global-setup.ts` 里启动服务的代码抽成可复用的函数。
   - **逐页走一遍并操作：** 工作台、站点列表、站点详情、站点表单（触发逆地理编码）、线路、站牌集、设置、API 文档页；再在页面里直接请求 `/_AMapService/…`。
   - **收集浏览器看到的全部内容：** 每个请求的地址、请求头、响应头、文本响应体。断言都不含哨兵值。
   - **检查服务端日志：** 把这个服务端进程的标准输出写到文件，断言也不含哨兵值。
2. **代理清洗上游响应：** 上游返回的文本响应里如果出现安全密钥，代理替换成 `***` 再转发；逆地理编码的错误信息不带上游地址。第 1 项的回显用例就是检查这一点。**默认，可改**
3. **用真实 Key 检查（验收）：** 新的 Playwright 项目 `real-amap`，默认不运行。
   - 对着本机的 Docker 部署跑：地址、账号取环境变量，高德变量用本机 `.env` 里的真实值。
   - 等真实地图瓦片加载出来，再做一次逆地理编码。
   - 收集包括高德域名在内的全部网络请求，断言不含真实的安全密钥和 Web 服务 Key。
   - 输出只报告出现次数与密钥长度，不打印值。

**后端测试内容：**

- **AC-17：**
  - 改了站点 A，没改 B；带改之前的时间调用，只返回 A。
  - 吊销 Token 后返回 401。
- **鉴权与只读：**
  - `/api/v1` 不认登录 Cookie；内部接口不认 Token。
  - Token 不能调用 Token 管理接口。
  - `/api/v1` 的非 GET 请求返回 404。
  - 最后使用时间按分钟节流写入。
- **"有变化"的口径（3.4、3.5 节）：**
  - 每条写入路径都会更新 `changedAt`：站点表单保存、站点导入、线路只改路径站、线路导入、改模式删走向、地标只改位置点。
  - 没有变化的保存不更新。
  - 被引用对象改名不更新引用方。
  - 站牌集：自身保存和连带修改会更新。
  - 线路停运：该线路所有站点的站牌集都会更新。
  - 只改到站时刻：不更新。
  - 加入站点 X：只更新 X 的站牌集。
  - 删除线路：包括只有待编排的站牌集在内全部更新。
  - 站点改名：不更新它的站牌集。
- **水位：**
  - 测试里开一个写事务改站点后先不提交，同时调用列表，`nextUpdatedSince` 不晚于该事务开始时间减 5 秒。
  - 事务提交后，用这个值做下一轮能取到该站点。
- **游标：**
  - 翻页过程中修改一个已读过的对象，不漏掉任何对象。
  - 游标不合法返回 400。

## 11. 默认决定汇总（可改）

| # | 决定 | 理由 |
|---|---|---|
| 1 | Token 为 `gt_` 加 32 字节随机数；存 SHA-256，不用会话密钥做 HMAC；另存前缀 | 换会话密钥不会让 Token 全部失效；前缀便于辨认和扫描泄露 |
| 2 | 吊销即删除记录；名称不能重名 | 单用户，不需要吊销记录；重名时分不清 |
| 3 | `/api/v1` 只认 Token，内部接口只认会话，Token 管理只认会话 | 规则简单；Token 泄露也碰不到写接口 |
| 4 | 游标分页，不用页码，不返回总数 | 页码分页在翻页期间有修改时会漏对象 |
| 5 | `nextUpdatedSince` 取当前时间和进行中写事务的最早开始时间里较早的一个，再减 5 秒 | 导入是长事务，只取当前时间会漏 |
| 6 | 被引用对象改名、扩展字段定义变化不算引用方"有变化" | 引用按 ID 关联，参考数据单独同步；否则改一个字典名要重传上万个站点 |
| 7 | 站牌集新增 `changedAt`；线路的编排投影（状态 + 走向种类 + 站序）变化时只更新途经实际变化的站点；停运、恢复时全部更新 | 满足需求第 11 节，又不让改到站时刻这类修改波及站牌集 |
| 8 | 已删除对象覆盖九种类型；非快照类型新建 `Tombstone` 表 | 地标、字典等也能删除，下游增量同步需要知道 |
| 9 | 加站架模板和扩展字段定义两个资源 | 需求 5.12 的"文件"包括模板示意图；没有定义，下游看不懂 `ext` |
| 10 | OpenAPI 由共享包的 zod 模式经 `z.toJSONSchema` 生成；文档页用本地 `swagger-ui-dist`；文档不需要 Token | 不维护第二套 DTO；内网能打开；文档里没有业务数据 |
| 11 | 文件走 `/api/v1/files/{id}`，输出相对路径；内部 `/api/uploads/:id` 仍只认会话 | 两个前缀各用一种鉴权方式 |
| 12 | 枚举输出代码值；坐标按 GCJ-02 原样输出 | 代码值稳定；转换坐标系由下游按需处理 |
| 13 | 不做 API 限流与 CORS | Token 猜不中；下游是服务端调用 |
| 14 | 应用容器启动时执行 `prisma migrate deploy` | 单机单实例最省事；升级只要换镜像 |
| 15 | 默认在所有网卡开放 8080；`TRUST_PROXY` 可配，compose 默认信任私有网段 | 内网开箱可用；放到反向代理后面时 Cookie 能正确加 `Secure` |
| 16 | 备份用独立容器；每天 02:30；数据库 `pg_dump -Fc`；上传文件用硬链接做增量的完整文件树；保留 30 天但始终保留最新一份 | 不往应用镜像里装 `pg_dump`；照片量大，不能每天打全量包 |
| 17 | 恢复前先给当前数据备份一份；整库重建后再还原 | 防止选错备份；不留下新版本的表 |
| 18 | 设置加只读的"备份"页签；工作台在备份超过 48 小时或失败时提醒 | 备份悄悄失败是最常见的事故 |
| 19 | 代理在上游文本响应里清洗安全密钥 | 防止上游回显时把密钥带给浏览器 |
| 20 | 演练在独立的 compose 项目里进行，原地恢复和新环境恢复各一次 | 不碰正式环境；新环境恢复才是换机器时真正要用的 |
| 21 | 提供离线打包脚本 | 内网服务器常常不能上网拉镜像 |
| 22 | 应用和备份容器时区设为 `Asia/Shanghai`，数据库保持 UTC；原生 SQL 写时间用 `now() AT TIME ZONE 'UTC'` | 备份按本地时间命名和定时；数据库时间不出现 8 小时偏差 |
| 23 | `limit` 默认 100，最大 500；线路、站牌集最大 100 | 每页都能在 1 秒内返回 |

### 12.3 与计划不同或计划未写明的地方

| 项 | 做法与原因 |
|---|---|
| 站点引用 | 计划写引用为 `{ id, name }`。站点引用（站牌集的 `stop`、路径站的 `stop`）另带 `direction`：同名站点靠方位区分 |
| `createdAt` | 计划只给站点列了 `createdAt`；所有资源都输出 `createdAt` 与 `changedAt` |
| 路径参数 | ID 不是 UUID 时返回 400（沿用内部接口的 `ParseUUIDPipe`）；按站点查站牌集时站点不存在，提示"站点不存在" |
| 已删除对象的排序 | 两个来源都按（删除时间，对象 ID）排序归并；墓碑表以对象 ID 为主键。快照表另加手写的部分索引 `("createdAt", "id") WHERE action = 'delete'`，Prisma 不认为有漂移 |
| 水位 | 只看 `backend_type = 'client backend'` 的连接，避免自动清理进程拖住水位 |
| 一页的事务 | `REPEATABLE READ` 之外再加 `SET TRANSACTION READ ONLY` |
| 文档页 | 由控制器只放行 swagger-ui 的 `swagger-ui.css`、`swagger-ui-bundle.js`、图标与自己的 `init.js`（不用内联脚本）；授权信息不存进浏览器 |
| 代理清洗 | 计划写清洗安全密钥。代理把文本响应里的安全密钥与 Web 服务 Key 都换成 `***`（原文与 URL 编码两种写法）；逆地理编码的结果也清洗。瓦片等二进制原样转发 |
| 真实 Key 检查 | 计划写"Playwright 项目 `real-amap`"。主配置有 globalSetup（起测试容器与服务端），所以放在单独的配置 `playwright.real-amap.config.ts`（项目名 `real-amap`），用 `pnpm -F @gentransit/web test:real-amap` 运行，主配置用 `testIgnore` 排除。JS API 2.0 的矢量瓦片直接来自高德域名，`/_AMapService` 只承担服务请求，所以检查改为"等真实瓦片 + 经代理做一次真实地点搜索" |
| Compose 项目名 | `docker-compose.yml` 固定 `name: gentransit-app`。开发库的 `docker-compose.dev.yml` 在同一目录，两者默认项目名都是 `gentransit`；不固定的话，正式部署会接管开发库的 `db` 容器 |
| 新增环境变量 | `GT_BACKUP_PATH`（备份目录在宿主机上的位置，默认 `./backups`）、`GT_ENV_FILE`（compose 读哪个 env 文件，默认 `.env`，演练用）、`APP_VERSION`（镜像构建时写入，OpenAPI 与备份清单用）、`AMAP_UPSTREAM_OVERRIDE`（只在 `NODE_ENV=test` 生效）、`GT_BUILD_PROXY`（只给 `deploy/build.sh` 用） |
| 高德变量进容器 | compose 的 `app.environment` 写 `AMAP_*: ${AMAP_*:-}`：取自 `.env` 或宿主机环境变量（宿主机优先）。本机的高德变量在用户环境变量里、`.env` 里没有，这样两种放法都能用 |
| 恢复 | 计划写"`docker compose run` 并把上传卷挂成可写"。compose 里加了 `restore` 服务（`profiles: [tools]`，平时不启动），上传卷可写，入口 `restore-inner.sh`；恢复后把上传文件的属主改成应用容器的 `node` 用户（uid 1000） |
| 备份的一致性 | 导出、各表行数与最后一个迁移在同一个只读快照里取（`pg_export_snapshot` + `pg_dump --snapshot`），清单与导出内容严格一致，恢复后的核对不会因为备份期间有写入而误报 |
| 备份清单 | 上传文件只记文件数与总大小，不逐个算 SHA-256（照片量大时每天全算太慢），演练脚本自己算全部文件的 SHA-256。清单另记 `hardlinked`：文件系统不支持硬链接时退回整份复制 |
| 失败记录与重试 | 失败原因写在 `backups/failures/<名称>.txt`，"备份"页签的日历据此标出失败日；失败后 1 小时重试，最多重试 3 次（共 4 次） |
| 备份页签的手册链接 | 应用里没有托管手册，页签写明手册路径 `docs/deploy.md` |
| 工作台提醒 | 没有配置备份目录（开发环境）时不提醒 |
| 脚本的调用方式 | 在 Windows 上提交的脚本没有可执行位，文档、界面与脚本之间一律写 `bash xxx.sh`；`.gitattributes` 让 `.sh` 与 `Dockerfile` 保持 LF |
| 构建代理 | 本机 Docker 客户端配置里的代理（127.0.0.1）会传进构建容器而连不上。`deploy/build.sh` 支持 `GT_BUILD_PROXY=direct` 或指定代理，不改本机的 Docker 配置 |
| 演练 | 两个环境依次用同一个项目名 `gentransit-drill`（A 清掉后再起 B），端口 18080 与 55439，自带随机的数据库密码与初始账号，不读根目录 `.env`；数据库端口是 54329 或种子连接串指向它时直接退出 |
| 端到端 | 起服务端的代码抽成 `e2e/server.ts`；globalSetup 把测试库连接串放进 `GT_E2E_DATABASE_URL`，AC-18 用例的第二个服务端连同一个库 |
| 恢复失败时（审查时补） | `deploy/restore.sh` 中途失败时 app 保持停止（库可能已删掉一半），并提示用 `-pre-restore` 备份恢复、排查后再启动；`.gitignore` 加上 `.idea/` |

### 12.4 已知问题

- 应用镜像约 970 MB，其中 Prisma CLI 及其依赖（Studio、pglite、effect、typescript 等）约 250 MB，只为启动时执行迁移。以后可以改成只带 schema engine 的精简迁移方式。
- 本机没有高德 Web 服务 Key，真实 Key 检查没有覆盖真实的逆地理编码；部署方配置后可再跑一次 `test:real-amap`（配置了 Key 时会点地图触发）。
- 地标、地标类别与各类基础数据没有快照，原样保存也会更新 `updatedAt`，下游增量同步会多取到这些对象（按 ID 覆盖，无害）。
- 一个长时间开着写事务不提交的连接会一直拖住水位，期间每一轮都会从那个时间点重新取；属于预期行为。
- 只读 API 没有限流，也没有逐次调用日志（计划第 1 节"不做"）。
- Windows 上的演练脚本依赖 Git Bash；第一次构建镜像要下载依赖，约 5 分钟。
- 沿用 M1：Prisma 7 的查询解释器在事务里并发取关联数据，pg 8 打印一条弃用警告，功能正常。

### 12.5 本地运行

- 开发：同 M1 计划 11.5。已有开发库升级到 M4 时执行 `pnpm install`（新依赖 swagger-ui-dist）与 `pnpm db:migrate`（新增迁移 `20261029020554_api_v1`）。只读 API 文档在服务端的 `/api/v1/docs`；Token 在"设置 → API Token"里新建。
- Docker 部署：见 `docs/deploy.md`。本机试跑：`GT_BUILD_PROXY=direct bash deploy/build.sh`；在 shell 里设好 `POSTGRES_PASSWORD`（根目录 `.env` 没有这一项）后 `docker compose up -d --no-build`；浏览器打开 `http://127.0.0.1:8080`，用 `.env` 里的初始账号登录；用完 `docker compose down -v`。
- 演练：`GT_BUILD_PROXY=direct bash deploy/drill.sh`（本机），结论写在 `deploy/drill-work/drill-report.md`。
- 真实 Key 检查：先按上一条起 Docker 部署，再执行 `pnpm -F @gentransit/web test:real-amap`（地址默认 `http://127.0.0.1:8080`，可用 `GT_REAL_BASE_URL`、`GT_REAL_USERNAME`、`GT_REAL_PASSWORD` 覆盖）。
- 离线包：`bash deploy/pack.sh`，产物在 `deploy/out/`。
