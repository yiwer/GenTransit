## 2. 线路的领域规则

### 2.1 模式与走向

| 模式 | 走向（按位置） |
|---|---|
| 单向 | 单向 |
| 双边 | 上行、下行 |
| 单环 | 环线 |
| 双环 | 内环、外环 |

**改模式时按位置对应。** 第 1 个走向原地改名并保留数据，例如双边改单向，上行就变成单向；多出来的走向删除，例如下行。这样走向 ID 不变，M3 的编排随之保留。需求 AC-16"双边改单向时提示下行编排将被删除"就是这个规则。表单里切换模式时，页签立即改名，将删除的页签标成删除样式；保存前弹窗确认，M3 起在弹窗里写明受影响的编排数。**默认，可改**

### 2.2 走向、路径站、途经

- 走向按（线路，走向）唯一，保存时原地更新，ID 保持稳定。M3 的编排以"走向 ID + 第几次途经"定位（需求 4.2 第 4 条）。
- 路径站每次保存整体替换。它的 ID 不对外承诺，快照和编排都不依赖它。
- 第几次途经实时计算：本走向中该站点第几次出现。
- 每个走向至少 2 个路径站（需求第 11 节），在保存时校验。新建线路时可以先只填线路属性，但每个走向都要有站序才能保存。
- 到站时刻按路径站存：每个路径站一组 `HH:mm`，按时间先后排列。表格里第 k 列就是每站的第 k 个时刻，各站可以不一样多。**默认，可改**

### 2.3 停运与恢复

- 单独的接口，请求里带 `rev`，即时生效。
- 线路自身存一份"修改"快照，说明写"停运"或"恢复运营"。只有线路自己生成快照，其他对象不生成（不扩散）。**默认，可改**
- 确认弹窗写明影响。M2 先写"经过 N 个站点"，M3 起改为"N 个站牌集的编排将显示为失效"。

### 2.4 排序

线路列表默认按自动排序规则（需求 5.5.6，`compareLineName` 已在共享包）。数据库排序规则表达不了这条规则。按设计上限 3000 条线路，做法是：

1. 先在数据库里按筛选条件取出 ID 和线路名。
2. 在服务端内存里排序。
3. 再取当前页的完整数据。

**默认，可改**

## 3. 后端

### 3.1 接口

| 接口 | 说明 |
|---|---|
| `GET /api/lines` | 筛选（名称、模式、公司、状态、经过的站点 `stopId`）、分页、排序（默认自动排序，可选线路名、最近修改）；每行带起终点、各走向站数 |
| `GET /api/lines/:id` | 详情：线路属性、各走向（服务信息、站序、每站第几次途经、到站时刻、扩展字段）、快照数 |
| `GET /api/lines/:id/transfers?routeId=` | 线路详情条形图用：该走向每一站可换乘的其他线路 |
| `GET /api/lines/check-name`、`check-number` | 线路名、管理编号重复的即时检查 |
| `POST /api/lines`、`PUT /api/lines/:id` | 整个聚合一次保存（线路 + 全部走向 + 路径站），PUT 带 `rev`；冲突返回 409 并带最新内容；没有变化返回 `changed: false` |
| `POST /api/lines/:id/suspend`、`/resume` | 带 `rev` |
| `GET /api/lines/:id/delete-check`、`DELETE /api/lines/:id` | 删除；确认弹窗写明"删除其全部走向与站序"，M3 起加上受影响的站牌集数 |
| `POST /api/stops/match` | 站名 + 方位批量匹配，供"粘贴两列文本"使用：返回匹配到的站点和未匹配的行 |
| `GET /api/snapshots?type=line…`、`/api/snapshots/deleted?type=line` | 复用 M1 |

### 3.2 线路快照（`LineSnapshotV1`）

```ts
{
  schema: 1,
  name, number, nameEn, mode, status, ticketType, fare,
  company: Ref | null, fareSystem: Ref | null,
  ext: Record<string, ExtSnapshotValue>,
  routes: {
    [kind in RouteKind]?: {
      serviceType, serviceTime, interval,
      stops: { id: `${stopId}#${pass}`, stop: Ref /* 名称写"站名（方位）" */, times: string[], ext: Record<string, ExtSnapshotValue> }[]
    }
  }
}
```

- 走向按走向名作键，路径站用"站点 ID + 第几次途经"作 ID。这样每次保存重建路径站不会产生假差异，站点改名也不会让线路生成快照（引用对象规范化后只留 ID）。
- 差异规格按 6 种走向生成：`routes.<kind>.serviceType` 等走向字段，以及 `routes.<kind>.stops`（列表，显示增、删、移动、修改）。
- `diffList` 需要扩展：列表项可以指定标签路径（这里是 `stop.name`），因为路径站对象不是 `{ id, name }`，现在的 `display` 显示不出名称。

### 3.3 预留给 M3 的接口

在共享位置定义 `RouteRemovalHook`：`onRoutesRemoved(tx, { routeIds, note })` 和 `countAffected(routeIds)`。删除线路、修改模式删除走向时，在同一事务里调用它。M2 的实现是空操作，返回 0；M3 实现"删除这些走向的编排，并给受影响的站牌集各存一份连带修改快照"。

### 3.4 导入

新增 `ImportJob` 表：

| 字段 | 说明 |
|---|---|
| 类型 | 站点 / 线路 |
| 状态 | 待确认、已确认、已取消、已过期 |
| 原文件名 | |
| 选项 | 坐标系 |
| 预览结果 | JSONB：新增、修改（含改动字段或站序差异）、无变化计数、失败行（行号、原因）、将新建的字典项与行政区划 |
| 计划哈希 | 见下面第 4 步 |
| 时间 | 创建时间、过期时间（24 小时）**默认，可改** |

流程：

1. `GET /api/import/:kind/template`：按当前启用的扩展字段生成模板。必填列名带 `*`，另附一个"说明"sheet。
2. `POST /api/import/:kind`（multipart，≤20 MB **默认，可改**）：解析、校验，生成预览，返回预览和 job ID，此时不写业务数据。
3. `POST /api/import/:id/confirm`：在一个事务里重新分析一次文件；分析出的计划和预览时不一致（比如这期间有人改了站点），就拒绝，提示"数据已变化，请重新预览"。一致就写入：新建字典项和行政区划，写对象；每个新增或修改的对象各存一份"导入新增"或"导入修改"快照，无变化的对象不存。整个导入是原子的。**默认，可改**
4. `POST /api/import/:id/cancel`；`GET /api/import/:id/failures`：下载失败行，原样附一列"失败原因"。

**站点导入：**

- 按（站名，方位）匹配，存在则修改，不存在则新增；修改时空单元格表示不改。
- 新增站点必须有坐标（需求第 11 节）。
- 方位值按当前方位模式校验。
- 坐标从 BD-09 或 WGS-84 转换到 GCJ-02，转换函数放共享包，单元测试用已知坐标对照。
- 市、区、街道按名称逐级匹配；路段、维护公司、站台类型、安全设施、候车亭类型这些字典按名称匹配。匹配不到的进"将新建"一栏。
- 新增站点同时建空站牌集，并存两份"导入新增"快照。

**线路导入：**

- 按管理编号分组。任一行失败（走向名与模式不符、序号重复或不连续、站点匹配不上、时刻格式不对、扩展字段不合法），整条线路失败，并列出全部原因和未匹配站点（BR-17）。
- 文件中出现的走向，站序整体替换；没出现的不变。
- 线路 sheet 里没有、但走向或路径站 sheet 里出现了的管理编号：线路已存在就只改走向，不存在就算失败。
- 文件里改了模式时，新模式下不存在的旧走向按 2.1 的规则删除，预览里列在"将删除的走向"。
- 到站时刻列用英文逗号、中文逗号、顿号或空格分隔都接受。**默认，可改**

**性能：** 1 万行文件在 1 分钟内出预览（需求 7.1）。匹配时先把全部站点的（站名，方位）键、字典名和区划树一次读进内存，不逐行查询。

### 3.5 导出

- 站点导出、线路导出的格式与对应模板完全一致，范围是当前筛选结果。
- 用 ExcelJS 的流式写出，2 万站点也不占满内存。
- 文件名形如 `站点_2026-10-28.xlsx`。
- 读写 Excel 统一用 ExcelJS（锁定精确版本）。**默认，可改**

**AC-11：** 导出后原样导入，预览应为新增 0、修改 0；全部行计入"无变化"。为此有三条约定：

- 导出的数值格式与导入解析互逆：经纬度保留 6 位小数；整数不带小数点。
- 空值导出为空单元格。
- 扩展字段按类型格式化：日期 `YYYY-MM-DD`、时间 `HH:mm`、文本列表用顿号连接。

## 4. 前端

| 页面 | 要点 |
|---|---|
| 线路列表 `/lines` | 按原型定稿：分栏、线路牌、悬停或单击时地图强调该线路的走向（F-COM-13）；宽表列按需求 5.4.2，可选择显示列；筛选进 URL；分页；已删除视图；导入、导出 |
| 线路详情 `/lines/:id` | 按原型定稿：大号线路牌、属性表、走向分段控件、服务信息卡、站序条形图（换乘线路牌；单击定位并浮出卡片，双击或回车进站点详情）、停运或恢复弹窗、修改历史按钮 |
| 线路表单 `/lines/new`、`/lines/:id/edit` | 原型没有做，按设计语言新做，见 4.1 |
| 导入 | 站点、线路共用一个导入抽屉，见 4.2 |
| 站点侧 | 列表加"经过线路"筛选（线路牌多选）；详情里的线路牌可点，进入线路详情；导入、导出菜单启用 |

### 4.1 线路表单

**布局：** 左表单、右地图（F-COM-11），左栏默认更宽，因为站序表需要空间。

**左栏，从上到下：**

1. **线路属性**（属性表）：线路名、管理编号（都做重复的即时检查）、英文名、模式、公交公司、售票类型、票制、票价、扩展字段。
2. **走向页签：** 页签数量随模式变化，改模式时按 2.1 改名或标删除。每个走向有：
   - 服务类型、服务时间、发车间隔。
   - **站序表：**
     - 每行：序号、站名、方位章、第几次途经（第 2 次起才显示）、到站时刻摘要、路径站扩展字段。
     - 拖拽把手排序（dnd-kit）；键盘可用 Alt+↑/↓ 移动。
     - 行内删除；"清空"需要确认。
   - **添加站点：** 搜索框按站名联想，选择时带方位；回车加到末尾，也可以插到选中行之后。
   - **粘贴两列文本：** 弹窗粘贴"站名 + 方位"（制表符或空格分隔），调 `/api/stops/match` 匹配。匹配到的行预览后追加；匹配不到的逐条标红，不追加。
   - **"反向生成"**：只在双边和双环下出现，用另一个走向的站序倒序生成本走向的初稿。旧系统没有，录入下行时很省事。**默认，可改**
3. **到站时刻编辑器**（每个走向一个弹窗）：
   - 行是路径站，列是"第 k 个时刻"。
   - 单元格可直接输入，也可以从 Excel 粘贴整块（制表符分隔）。
   - **按间隔填充：** 输入首站时刻（逗号分隔，或首班、末班和发车间隔）和站间用时（统一的分钟数，或逐段填写），依次推算后续各站。
   - 时刻格式与"按时间先后排列"都即时校验。
4. **底部状态栏：** "未保存：改了哪些字段"，以及保存按钮；有将删除的走向时，保存前确认。

**右侧地图：**

- 当前走向按站序连线，并标出行驶方向；其他走向淡显。
- 站点上标序号。
- 单击站序表的一行，地图定位到该站；单击地图上的站点，选中站序表里对应的行。

**未保存拦截与冲突弹窗**沿用站点表单的做法（草稿状态 + 共享包里的 zod 模式）。

### 4.2 导入抽屉

分三步：

1. **选择文件：** 下载模板；上传；站点导入另选坐标系。
2. **预览**，页签分为：
   - 新增
   - 修改：每行展开看改动字段，线路看站序差异，复用快照差异组件。
   - 失败：行号和原因；线路导入另列未匹配站点。
   - 将新建的字典项（只有站点导入有）
   - 将删除的走向（只有线路导入有）
   - 顶部显示无变化计数。
3. **确认或取消。** 确认成功后显示印章对勾和各类计数，可以下载失败行。

预览期间用轨道加载动画；1 万行以内的文件不做进度条。**默认，可改**

### 4.3 地图组件

在 `MapProps` 加 `routes?: MapRoute[]`：

```ts
interface MapRoute {
  id: string
  points: LngLat[]
  tone: 'strong' | 'normal' | 'faint'
  flow?: boolean
}
```

自绘 SVG 覆盖层负责折线和流动短划（原型 `FakeMap` / `RealMap` 的做法），示意平面同样支持。

## 5. 并发、有效修改、快照（沿用 M1）

- 线路带 `rev`，整个聚合一次保存。
- 先按条件更新再比较哈希：没有变化就回滚，不写快照，`updatedAt` 也不变。
- 停运和恢复同样带 `rev`，会让已打开的线路表单在保存时收到冲突提示。这是预期行为。
- 导入不检查 `rev`（它不是从某个打开的版本出发编辑），但会让之后用旧 `rev` 保存的表单收到冲突。

## 9. 默认决定汇总（可改）

| # | 决定 | 理由 |
|---|---|---|
| 1 | 改模式时按位置对应：第 1 个走向原地改名，多余的删除 | 与 AC-16 一致；走向 ID 稳定，M3 的编排得以保留 |
| 2 | 到站时刻按路径站各存一组，按时间先后排列；表格第 k 列 = 第 k 个时刻 | 与需求的字段定义一致，不引入"班次"实体 |
| 3 | 停运、恢复给线路自身存一份"修改"快照 | 状态是线路的字段；不扩散到其他对象 |
| 4 | 线路列表默认排序在服务端内存中完成 | 自动排序规则无法用数据库排序规则表达；规模上限 3000 条 |
| 5 | 路径站快照 ID = 站点 ID + 第几次途经 | 重建路径站不产生假差异 |
| 6 | M3 的连带影响用 `RouteRemovalHook` 预留，M2 为空实现 | M2 没有编排表 |
| 7 | 导入任务 24 小时过期；文件 ≤20 MB；确认时重新分析，与预览不一致就拒绝；整个导入原子提交 | 避免按过期预览写入；失败时不留半截数据 |
| 8 | Excel 统一用 ExcelJS | 读写都支持，有流式写出，npm 上持续维护 |
| 9 | 线路表单加"反向生成"下行 / 外环站序 | 录入效率；只生成草稿，不自动保存 |
| 10 | 到站时刻列接受多种分隔符 | 用户的 Excel 来源不一 |
| 11 | 导入预览不做进度条，只用加载动画 | 1 万行在 1 分钟内完成；以后需要再加 |

### 10.3 与计划不同或计划未写明的地方

| 项 | 做法与原因 |
|---|---|
| 到站时刻的先后 | 计划写"按时间先后排列"。实现为：严格递增，允许跨过一次午夜（夜班如 23:50 → 00:10），重复视为不合法。需求 5.4.1 已补写 |
| 时刻分隔符 | 除计划列的英文逗号、中文逗号、顿号、空格外，也接受分号 |
| 站点列表"经过线路"筛选 | M1 的 `line=`（线路名）改为 `lineIds=`（逗号分隔的线路 ID），对应界面的线路牌多选；导出接口同样适用 |
| `RouteRemovalHook` 的位置 | 计划写"共享位置"。它要拿事务句柄，所以放在服务端 `apps/server/src/lines/route-removal.hook.ts`，用注入令牌 `ROUTE_REMOVAL_HOOK` 提供；M2 是 `NoopRouteRemovalHook`。M3 换成真实实现即可，线路服务不用改 |
| 删除检查 | `GET /api/lines/:id/delete-check` 返回走向数、站点数、受影响站牌集数（M2 恒为 0） |
| 地图数据 | 线路列表每行、站点详情的经过线路都带各走向的站点坐标 `path`，地图直接画，不再单独请求。折线按站序直线连接，不做道路吸附（需求 Q13） |
| 示意平面 | 容器量出实际尺寸后重新适配视野；坐标刻度避开左下角比例尺 |
| 导入任务存原文件 | `ImportJob` 用 bytea 存上传的文件，确认时据此重新分析。确认、取消、过期后清掉文件；每次上传时把超时未确认的任务标为已过期，并删除 7 天前的任务 |
| 计划哈希 | 计划里带上已有对象的 `rev`。只比较要写入的值时，预览后有人改了同一站点的其他字段检测不到 |
| 错误码 | 数据已变化：409 `IMPORT_STALE`（附新的预览）；任务已确认、已取消或已过期：409 `IMPORT_CLOSED` |
| 确认事务超时 | 放宽到 10 分钟（Prisma 默认 5 秒）。1 万行确认实测约 10.5 秒 |
| 失败行下载 | 线路导入按原来的三个 sheet 分别列出失败线路的全部行，每个 sheet 都附"失败原因"列 |
| Excel 单元格 | 用户在 Excel 里编辑后，单元格可能被自动识别为日期：纯时间（1899-12-30 基准）读回 `HH:mm`，其他读回 `YYYY-MM-DD`；富文本、公式结果、超链接取显示文本 |
| 上传大小提示 | 超限多由 multer 先拦下，全局异常过滤器按接口写明上限：导入"文件不能超过 20 MB"，照片仍是"文件不能超过 10 MB" |
| 列选择器 | 从站点页抽成通用组件 `components/gt/columns.tsx`，线路宽表复用 |
| 全局搜索 | 线路在前（最多 5 条），站点在后（最多 8 个） |
| 线路批量读取 | 线路导出、导入分析用 `LineService.details` 分批（每批 500 条）读取，不逐条查询 |
