## 2. 领域规则（共享包，前后端共用）

新文件 `packages/shared/src/assist.ts`，放纯函数，全部有单元测试。

### 2.1 距离

- `distanceM(a, b)`：两点球面距离（米），haversine，地球半径 6371008.8 m。GCJ-02 坐标直接计算，城市尺度的误差可以忽略。
- 平面计算（2.3 的叉积）用以第一个点为原点的局部等距投影：x = Δlng·cos(lat₀)·111320，y = Δlat·110540。

### 2.2 对向站点（BR-19）

- `OPPOSITE_DIR = { 东: '西', 西: '东', 南: '北', 北: '南' }`。
- `oppositeDirOf(dir, mode)`：
  - 方位模式下返回相对方位。
  - 方位为"无""场站"，或编码模式时返回 `null`，表示"同名的任意其他站点"。
- `OPPOSITE_MAX_M = 300`（**默认，可改**，第 11 节）。
- 判定放在服务端 `StopService.opposites(ids)`，一条 SQL 完成：
  - 用站名过滤，走 `(name, direction)` 唯一索引的前缀。
  - 先用经纬度包围盒（±0.003°）预筛，再用 haversine 精确过滤。
  - 每个站点取最近的一个，返回 `Map<id, StopRef | null>`。

### 2.3 方位疑似反了（BR-20）

`wrongSide(prev | null, cur, next | null, opposite) → boolean`：

1. 行驶方向 v 取 `next − prev`。首站取 `next − cur`，末站取 `cur − prev`。
2. 侧向量 s(p) = cross(v, p − 基点)，基点取 prev（首站取 cur）。按 x 向东、y 向北，s < 0 表示在右侧。
3. 当 `s(opposite) < s(cur) − 5 m·|v|` 时判为反了，即对向站比本站更靠右，且超出 5 米容差（**默认，可改**）。
4. 没有前后站、或 v 长度小于 10 m 时不判断。

前端线路表单（A2 的行提醒）和服务端数据体检（V3）用的都是这个函数。

### 2.4 插入位置建议（第 11 节）

`suggestInsert(stops: LngLat[], x: LngLat) → { at: number; reason: 'between' | 'head' | 'tail' }`：

- 中间位置 i 的代价是 d(i, X) + d(X, i+1) − d(i, i+1)。
- 插在首站之前的代价按 d(X, 0) 计，插在末站之后按 d(last, X) 计。
- 取代价最小的位置；`at` 是插入后 X 在站序里的下标。

### 2.5 相邻站距离

- `gapWarnings(stops, limit = STOP_GAP_WARN_M)` 返回超阈值的行下标。
- `STOP_GAP_WARN_M = 3000`（Q74）。

### 2.6 站牌集：全部放到（A7）与从其他站点复制（C4）

两个函数都加在 `packages/shared/src/sign-set.ts`，与现有草稿操作同样返回新草稿，并可撤销。

`placeAll(draft, pool, targetBoardId, info)`：

- 整版站牌：依次调用 `placeOnBoard` 放上全部 `status === 'waiting'` 的途经，再调用 `autoSort`。
- 分片站牌：按插片编号依次调用 `placeOnSlot` 放进空的线路插片，返回 `{ draft, placed, left }`。

`copySignSet(target, source, opts)`：

- `opts` 包含：`sourceRoutes: RouteInfo[]`，对方站点的走向信息，用来知道每条编排属于哪条线路；`targetPool: PoolItem[]`。
- **结构：** 对方站架按排列顺序整体追加。
  - 站架、站牌编号取下一个可用值，编号用完时抛 `DraftError`，提示还能放下几个站架。
  - 插片编号保持不变，因为插片编号在所属站牌内唯一。
  - ID 全部新生成，返回旧站牌、插片 ID 到新 ID 的映射。
- **编排（BR-21）：** 对每条源编排：
  1. 取它的线路 L。
  2. 只有本站途经里属于 L 的恰好一条、且这条状态为待编排时才映射。
  3. 放到映射后的站牌或插片上；整版站牌保持源顺序。源是隐藏的就隐藏。
- 返回 `{ draft, structure: { shelves, boards }, mapped, skipped }`，界面据此提示"带过来 5 条编排，2 条留在待编排"。

### 3.2 线路的成组写入（A4、A5，BR-22）

**重构：** 把 `LineService.update` 的事务体抽成 `updateIn(tx, id, input, opts: { note?: string })`。

- 现有的 `update` 改为调用它，行为不变。
- `note` 不为空时写进快照说明，代替"修改：字段名"。

**`join` 与 `replace` 的流程：**

1. 在一个事务里逐条线路读取当前详情。`rev` 与请求里的不同时，记进冲突列表。
2. 有任何冲突就整组回滚，返回 409，`details.lines` 列出线路名。前端提示"这些线路刚刚在别处修改，请刷新后重试"，并自动重新读取引用。
3. 从当前详情构造 `LineInput`：
   - **join：** 在走向 `kind` 的下标 `at` 插入 `{ stopId, times: [], ext: {} }`。同一走向有多个插入时，按 `at` 从大到小插入，避免下标错位。
   - **replace：** 把走向 `kind` 下标 `index` 的 `stopId` 换成 `targetId`，`times` 和 `ext` 保留。下标处的站点不是本站时，按冲突处理。
4. 调用 `updateIn`，快照说明：join 为"站点 X 加入站序"，replace 为"站点 X 替换为 Y"。
5. 返回 `{ lines: [{ id, name, changed }] }`。
6. 已有链路照常工作：
   - 修改时钟（M4 的 `touchedStops`）照常更新受影响站点的 `changedAt`。
   - 轨迹因站序变化标为过期（现有逻辑）。

**校验：**

- `targetId ≠ 本站`，目标站点必须存在。
- 替换后与前一站或后一站相同（出现连续重复）时，服务端同样拒绝该处，返回 422 并说明是哪一处。前端默认不勾这类引用。

### 3.3 批量修改站点（A6）

**重构：** 把 `StopService.update` 的事务体抽成 `updateIn(tx, id, input, opts)`，与 3.2 相同。

**流程：**

1. 解析 `scope`，得到站点 ID。
2. 一个事务里逐站读取当前详情，套用补丁，得到新的 `StopInput`。
3. 内容相同的站跳过：快照 `record` 返回 `written=false`，现有的有效修改判定。
4. 变化的站点写入，各存一份"修改"快照，说明"批量修改：维护公司、路段"，只列这个站点实际变化的字段。

**其他约定：**

- **冲突与并发：** 不检查 `rev`（BR-22 的例外）：补丁按字段覆盖，与打开时间无关。写入时照常递增 `rev`，正在编辑这些站点的表单保存时会得到冲突提示。
- **性能：** 设计规模下 2000 个站点在 30 秒内完成（第 6 节性能测试），先把补丁涉及的字典、区划、扩展字段定义一次性读好。
- **预览：** `preview` 只读，按同样逻辑计算 `changing`，不写入。

### 3.4 沿线编排进度（V1）

`GET /api/lines/:id/arrangement` 返回：

```text
{
  suspended: boolean,
  routes: [{ routeId, kind, stops: [{ stopId, pass, status: 'placed' | 'hidden' | 'waiting' }] }],
  invalid: [{ stopId, name, direction, count }],   // 不在站序上、但仍留有本线路编排的站点
  totals: { placed, hidden, waiting, invalidStops }
}
```

**查询：**

- 本线路各走向的路径站，开窗口得到"第几次途经"。
- 左连接 `Schedule`，条件是同一 `routeId`、`pass`，且在该站点的站牌集里。有放在站牌或插片上的编排为已编排，只有隐藏编排为隐藏，没有编排为待编排。
- `invalid` 是本线路各走向在 `Schedule` 里出现、但对应途经已不在站序中的站点，按站点汇总条数。

**性能：** 线路停运时 `routes[].stops[].status` 不计算，只返回 `suspended: true`。设计规模下单条线路在 200 ms 内返回。

### 3.5 编辑器队列（F1）

`GET /api/sign-sets/queue` 按来源返回 `{ stopIds: uuid[], total }`，最多 500 个（**默认，可改**）：

| `from` | 参数 | 顺序 |
|---|---|---|
| `list` | 站牌集列表的全部筛选与排序参数 | 与列表完全相同（复用 `SignSetService.ids`，不分页） |
| `home` | 无 | 等同 `list` 的 `pending=1&sort=-pending` |
| `line` | `lineId` | 按 3.4 的结果：先第一个走向里待编排的站，按站序；再第二个走向的；再 `invalid` 里的站。站点去重，保留第一次出现的位置 |

### 3.6 数据体检（V3）

`DataCheckService.counts()` 返回各检查项的数量。`ids(key)` 供列表的 `check` 筛选使用。

| 键 | 对象 | 判定 | 实现 |
|---|---|---|---|
| `noNameEn` | 站点 | 英文名为空 | SQL |
| `noRegion` | 站点 | 区、街道、路段任一为空（市不单独查，区有值时市一定有值） | SQL |
| `noShelf` | 站点 | 有运营中线路经过，但站牌集没有站架 | SQL |
| `noPhoto` | 站点 | 没有照片 | SQL |
| `noTrack` | 线路 | 有走向没算轨迹 | SQL |
| `trackStale` | 线路 | 有走向的轨迹已过期 | 复用走向轨迹的过期判定（`5a5d8b7` 引入的 `RouteTrackService`） |
| `gap` | 线路 | 有相邻两站距离超过 3 km | SQL：`lag()` 加 haversine |
| `wrongSide` | 线路 | 有路径站方位疑似反了 | Node：读出全部路径站坐标与对向站（一次 2.2 的批量查询），用 2.3 的函数 |
| `pending` | 站牌集 | 有待编排或失效 | 复用 `SignSetStatusService.summary` |

- 设计规模（站点 2 万、线路 3000）下 `counts()` 在 2 秒内返回。
- `wrongSide` 和 `gap` 的线路 ID 集合在服务内缓存 60 秒（**默认，可改**）。任何线路或站点保存后清空缓存，列表的 `check` 筛选与工作台数字因此一致。

## 4. 前端

新组件都按设计语言来：暖纸底，墨绿是主操作色；状态语义沿用待编排、已编排、隐藏、失效四种；灵动的 SVG 只用在关键瞬间，并尊重"减少动效"。

### 4.1 编辑器队列（F1）

- **URL：** `/sign-sets/:stopId?from=list&<列表参数>`、`?from=home`、`?from=line&lineId=…`。
- **新文件** `features/sign-sets/queue.ts`：
  - 第一次进入时请求 3.5 的接口，把 `stopIds` 存进 `sessionStorage`，键为 `gt-queue:` 加上来源参数的规范化字符串。
  - 之后在队列里前后移动都读这份快照，顺序不变。
  - 记录本轮已保存过的站点，用来把轨道上的点画成已处理。
  - 当前站不在快照里时（例如直接改了 URL），视为没有队列。
- **`QueueTrack` 组件**，放在编辑器顶部标题右侧：
  - 一条细的墨绿轨道，站点画成圆点：已处理是鼠尾草实心，当前站放大并加一圈定位涟漪，其余空心。
  - 超过 15 站时只画当前站前后各 7 站，两端用"…"。
  - 文字为"第 3 / 12 站"。左右有上一站、下一站按钮，悬停显示站名。
- **保存：** 有队列时，保存按钮旁多一个"保存并下一站"（Ctrl+Enter）。
  - 下一站时没有未保存修改就直接进入；有修改时弹出"保存并进入下一站 / 放弃修改 / 留在这里"。
- **处理完：** 最后一站保存后，印章对勾加"这一轮处理完了"，按钮"回到来源"。
- **返回链接：**
  - `list` 回到 `/sign-sets` 加原参数（含页码）。
  - `home` 回到 `/home`。
  - `line` 回到 `/lines/:id`。
- **入口：**
  - 工作台待处理前 5 项，用 `from=home`。
  - 站牌集列表"编排"，用 `from=list` 加当前参数。
  - 线路详情"逐站编排"，用 `from=line`。

### 4.2 线路详情：沿线编排进度（V1）与保存后提示（F2）

- **状态点：** 站序条每行最右侧加一个 10 px 的状态点。
  - 已编排：鼠尾草实心。
  - 待编排：赭石，带呼吸点。
  - 隐藏：虚线圈。
  - 悬停显示"在本站：已编排在三号牌"等说明。
  - 读取 3.4 的接口，与线路详情同时请求。
- **汇总：** 走向切换下方一行"沿线 24 站：已编排 20 · 待编排 3 · 隐藏 1"。有 `invalid` 时再一行"另有 2 站留有本线路的失效编排"。
- **逐站编排：** 有待编排或失效编排时，右侧显示"逐站编排"按钮，进入 4.1 的 `from=line` 队列。

- **保存后提示：** 线路表单保存后带路由状态 `justSaved` 进入详情。汇总有待处理时，这一行出现一次赭石呼吸点，"逐站编排"按钮用主色。

### 4.4 从其他站点复制（C4）

- **入口：** "站架"菜单新增"从其他站点复制…"，弹出对话框。
- **对话框：**
  - 顶部是站点搜索（`near` 设为本站，结果显示距离）。
  - 搜索框为空时列出建议：先列对向站，再列其他同名站。用一对相对的方位章作图标。
  - 选中后下方用 `SignSetGlance` 预览对方立面，并给出预计结果："将追加 2 个站架、5 块站牌；可带过 6 条编排"。前端用 2.6 的函数先算一遍。
  - 确认后执行，可撤销。
- **从新建对向站点进入：** C1 的"照着原站复制站牌集"进入编辑器时带 `?copyFrom=<原站 id>`，对话框自动打开并选中原站。

### 4.5 新建对向站点（C1）与新建后下一步（F2）

- **入口：** 站点详情的更多菜单"新建对向站点"，进入 `/stops/new?oppositeOf=<id>`。
- **初稿：** 表单按 5.3.3 带入字段：
  - 标题区显示"对向于 某站（东）"，并配一个小的相对方位章。
  - 地图以原站为中心，原站画成淡显的点；标记为空，底部提示"点击马路对面放置"。
- **已有对向站：** 进入时调用 `opposites`。已经存在时，表单顶部提示"300 米内已有「某站（西）」"，并给出链接，但不阻止新建。
- **"下一步"卡片：** 新建保存后进入详情，带路由状态 `created`（对向新建时还带 `oppositeOf`）。详情顶部出现这张卡片：
  - 三个入口：装站牌、新建对向站点、加入线路。对向新建时多一项"照着原站复制站牌集"。
  - 卡片可以关闭，刷新后不再出现。

### 4.6 加入线路（A4）

- **对话框**，标题"把 某站（东）加入线路"，分两步：
  1. **选线路：** 按名称搜索线路。搜索框为空时先列出附近 500 m 内其他站点经过的线路（**默认，可改**），因为新站通常是这些线路要停的。
  2. **确认位置：** 每条选中的线路每个走向一行：
     - 勾选框（默认勾）。
     - 站点：本站或对向站，双向线路的第二个走向默认用对向站，没有时用本站并标出。
     - 建议位置"插在 A 与 B 之间"，下拉可改成任意位置或首末站。
     - 右侧是这个走向站序的微型条形图，标出插入点。
- **确认：** 调用 `join`，成功后提示"已加入 3 条线路"，并刷新本站的经过线路。

### 4.7 在线路中替换（A5）

- **入口：** 站点详情的更多菜单"在线路中替换为…"，以及删除被拒的对话框。删除被拒时，`ReferrerList` 的线路名改成链接。
- **对话框：**
  1. 上方选目标站点：搜索，`near` 设为本站。
  2. 下方列出每处引用：线路牌、走向、第 n 站，以及"前一站 → 本站 → 后一站"。每行一个勾选框。替换后会出现连续重复的行默认不勾，并说明原因。
- **确认：** 调用 `replace`。成功后本站不再被引用时，对话框变成"已替换 4 处。现在可以删除这个站点"，带"删除站点"按钮，走现有的删除确认。

### 4.8 批量修改站点（A6）

- **勾选：** 站点列表宽表加一列勾选框，窄列表在行左侧悬停时出现勾选框。
  - 勾选结果存在页面状态里，跨页保留；换筛选时清空。
  - 表头勾选框只勾本页。
- **底部操作条：** 有勾选时浮出，内容为"已选 12 个站点"、"选择当前筛选的全部 356 个"、"批量修改"、"取消选择"。
- **对话框：**
  - 每个字段一行属性表，字段取值分"不改 / 设为… / 清空"三档，默认"不改"。
  - 区划是三级联动的一组。字典字段可以直接新增（F-COM-07）。
  - 底部实时预览（防抖调用 `preview`）："选中 30 个，将变化 25 个"，可展开前 10 个的改动。
- **确认：** 确认后显示进度动画，完成后提示"已修改 25 个站点，各生成一份修改快照"，并刷新列表。

### 4.9 线路表单（A1、A2、A3、V4）

- **反向生成（A1）：** 调用 `opposites` 后替换站点。
  - 没有对向站的行加一个赭石小标"沿用原站"。
  - 标记存在行的临时状态里，不进草稿比较；这一行被移动以外的方式改动后标记消失。
- **加站搜索（A2）：**
  - `StopSearch` 新增 `near` 参数：取选中行，没有选中行时取最后一行。
  - 结果显示"距上一站 420 m"，超过 3 km 的显示为赭石色。
- **行提醒（A2、BR-20）：**
  - 站序表对每行计算 `gapWarnings` 与 `wrongSide`。对向站来自对整个走向调用一次 `opposites`，按站点 ID 集合缓存。
  - 行尾显示提醒图标。悬停说明原因；方位反了的行带"换成对向站"按钮。
- **地图点选（A3）：**
  - 地图比例尺在"1 公里"档以内时，按视野请求 `in-view`（防抖 300 ms，排除当前走向已有的站），画成淡显的小点。
  - 单击淡点即调用 `addStops`，点上浮出"已加入 · 第 8 站"，并有短暂的涟漪。
- **改动对比（V4）：**
  - 编辑已有线路时，按"站点 ID + 第几次途经"比较当前走向与打开时的站序：新增的行在序号旁标墨绿"新"；被移除的站列在表下方，陶土色删除线，每个带"放回"（插回原来的前一站之后）。
  - 地图上新增的点用墨绿环，移除的点用陶土色空心点。
  - 新建线路时不显示。

### 4.10 复制为新线路（C3）

- **入口：** 线路详情的更多菜单"复制为新线路"，进入 `/lines/new?copyFrom=<id>`。
- **初稿：** 表单按 5.4.3 生成初稿。线路名和管理编号为空，占位文字是"复制自 K1路"；页头 eyebrow 显示"新建线路 · 复制自 K1路"。

### 4.11 工作台：数据体检（V3）

- **位置：** 在"最近修改"下方，或放在右栏快捷新建之上，按现有一屏三块的版式安排，不做成通用卡片仪表盘。
- **"数据体检"一节：**
  - 每个检查项一行：手绘感的小勾或圈，加名称和数量。数量为 0 时显示鼠尾草小勾并淡显；大于 0 时显示赭石数字，点击进入带 `check` 参数的列表。
  - 全部为 0 时显示一枚印章"数据完整"。
- **列表页：** 站点、线路列表认 `check` 参数。筛选区出现一枚可清除的"体检：缺英文名"标签。

### 4.12 地图与通用（A9、F3）

- **地图初始视野（A9）：**
  - 地图组件在用户平移、缩放结束时，把视野写进 `sessionStorage` 的 `gt-last-view`。
  - 没有 `fit` 点时，依次用：`gt-last-view`、`/api/stops/extent`（在应用启动时随配置读取，缓存）、`DEFAULT_CENTER`。
- **地图组件改动**（`MapProps`，高德与平面两种实现都要支持）：
  - `MapPoint.tone?: 'faint' | 'added' | 'removed'`。
  - `onViewport?(bbox, mpp)`。
- **Ctrl+S（F3）：** 线路表单与站牌集编辑器加 Ctrl+S，写法沿用站点表单。编辑器里焦点在输入框时同样生效。

## 5. 并发、有效修改、快照

- **成组写入（A4、A5）：** 一个事务，整组成功或整组不写。任何线路的 `rev` 对不上就整组拒绝，返回 409。
- **批量修改（A6）：** 不检查 `rev`，但每个站点照常递增 `rev`。
- **快照：** 三种操作都按有效修改判定。说明文字：

| 操作 | 快照对象 | 动作 | 说明 |
|---|---|---|---|
| 加入线路 | 每条线路 | 修改 | 站点 X 加入站序 |
| 替换站点 | 每条线路 | 修改 | 站点 X 替换为 Y |
| 批量修改 | 每个变化的站点 | 修改 | 批量修改：字段名 |

- **站牌集草稿操作：** 全部放到、从其他站点复制都只改草稿。用户保存时照常生成一份站牌集快照，可以撤销、重做。
- **修改时钟：** 加入线路、替换站点改了站序，M4 的 `touchedStops` 会更新受影响站点的站牌集 `changedAt`，下游增量同步不会漏。

### 10.2 与计划不同或计划未写明的地方

| 项 | 实际做法 |
|---|---|
| 批量修改的写入 | 没有抽 `StopService.updateIn`：批量路径先算出每站真正会变的字段，只写这些站点；改动前成批读出这些站点的完整行和补丁引用的名称，在内存里套上补丁组装快照内容，不读经过线路与站牌集计数（快照不含派生信息）。第一版逐站读完整详情，2000 站要 45 秒；现在每站只剩一次更新和快照的一读一写，8.7 秒 |
| 超过上限、引用不存在 | 统一返回 400（与现有校验错误一致），计划写的是 422 |
| 数据体检缓存 | 不按 60 秒过期，改为按"线路、走向、站点的最后修改时间与数量 + 方位模式"作版本，版本变了才重算；保存后立即反映，不用等 |
| 视野接口 | `GET /api/stops/in-view` 不带 `exclude`（一个走向最多 500 站，放进查询串太长），由前端过滤掉已在站序上的站 |
| 加入线路时用本站还是对向站 | 先按几何判断：本站在建议位置处方位反了、而对向站不反时改用对向站；判断不出来时才按"第二个走向用对向站"（默认决定 9） |
| 站牌集视图 | `SignSetView.stop` 多带经纬度（可选字段），从其他站点复制时按距离找站；快照与只读 API 不变 |
| 地图初始视野 | `MapView` 首次渲染前取一次 `/api/stops/extent`（10 分钟内复用）；高德与示意平面在平移、缩放结束后都把视野记进 `sessionStorage` |
| 队列轨道 | 上一站、下一站按钮只写"上一站""下一站"，不显示站名（队列快照里只有站点 ID） |
| 沿线状态点的悬停说明 | 只写"本线路在该站：已编排 / 待编排 / 隐藏"，不写在哪块牌上 |
| 一次性的路由状态 | 新增 `useNavStateOnce`：读出"刚新建""刚保存"后立即清掉，刷新或前进后退不再出现；线路详情的保存后提示也改用它 |
| 删除被拒的引用列表 | `ReferrerList` 增加可选 `hrefOf`，站点删除被拒时线路走向可点开 |
| 进度与体检的刷新 | 站牌集保存后使 `['lines','arrangement']` 与 `['data-checks']` 失效，这两个查询的 `staleTime` 设为 0，回到线路详情或工作台总是最新（端到端发现：逐站编排处理完回到线路，进度还是旧的） |
| 编辑器读取 | 编辑器进入时总是重新读取站牌集，不用站点详情页留下的缓存；加入线路、替换站点后也使站牌集缓存失效（端到端发现：新站加入线路后马上"照着原站复制"，因为途经是旧的，编排一条也没带过来） |
| 停运时的汇总 | 线路停运时汇总行写"沿线各站的编排此时都显示为失效"，不再重复页面上已有的"停运中"提示 |

### 10.3 已知问题
