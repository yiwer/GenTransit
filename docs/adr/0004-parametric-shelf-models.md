# 站架类型用"结构形式 + 参数"定义，2D 立面与 3D 由前端生成，不上传模型文件

M7 把站架类型从字典里的一个名称，升级为带结构的站架类型：单立柱、双立柱、候车亭、多面柱、附着式、电子站牌立杆六种形式，每种形式有若干毫米参数（柱高、柱距、顶棚下沿高、面数等）。编排页的 2D 立面（SVG）与 3D 预览（three.js）都由前端按参数实时生成，用同一个几何模块算出各面结构与挂牌位置。没有选择"每个类型上传 SVG + GLB 模型文件"：站架都是柱、牌、棚、箱的简单几何，参数足以描述；参数生成的 2D 与 3D 同源，牌面能按毫米与结构精确对齐，不需要会建模的人维护文件，也不必约定模型里的挂牌节点。

## Considered Options

- 上传模型文件为主（SVG + glTF/GLB）：外观自由，但每个类型都要建模，并在模型里标出挂牌位置；2D 与 3D 两份文件可能不一致。
- 参数化 + 可选 GLB 外观：保留为将来的扩展方向。需要厂家真实外观时，只替换 3D 外观，挂牌位置仍按参数算。

## Consequences

- 改站架类型的参数立即影响所有引用它的站架的展示。参数不进站牌集快照，修改历史里只看得到类型名称。
- 结构细节受限于参数，做不出任意造型。某个站架尺寸特殊时，另建一个站架类型。
- 3D 依赖 three.js，单独分包懒加载，不影响首次访问。
